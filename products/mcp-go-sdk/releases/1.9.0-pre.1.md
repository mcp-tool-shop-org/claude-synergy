# mcp-go-sdk v1.9.0-pre.1

In this release we introduce fixes, hardening, and small API additions on top of [v1.8.0](https://github.com/modelcontextprotocol/go-sdk/releases/tag/v1.8.0). It adds no new protocol revision: `2026-07-28` remains the newest version the SDK negotiates.

Most changes tighten spec compliance (standard JSON-RPC error codes, exact JSON number decoding without `float64` rounding, SEP-2243 HTTP headers, MRTR, and OAuth/OIDC validation), bound peer-controlled inputs, and add hooks for stream keep-alives, per-session notifications, and middleware.

Eight new `MCPGODEBUG` flags let you revert individual behavior changes, and seven flags from `v1.7.0` are removed as scheduled; see below.

## Hardening

HTTP clients no longer follow cross-origin or method-changing redirects unless the `http.Client` sets its own `CheckRedirect` (`StreamableClientTransport`, `SSEClientTransport`, and OAuth requests). The stdio frame cap now holds across arbitrary read boundaries, `CommandTransport` gains `MaxLineLength`, `StreamableClientTransport` applies `DefaultMaxEventSize` when unset, and `ParseWWWAuthenticate` runs in linear time. On the client, the `prompts/list`, `resources/list`, `resources/templates/list`, and `resources/read` caches are capped at 512 entries each and no longer retain results with `ttlMs <= 0`.

## Streams, per-session notifications, and middleware APIs

`StreamableHTTPOptions.StreamKeepAlive` sends periodic SSE comments on idle POST response streams (30s by default; negative disables) so proxies do not drop `subscriptions/listen` or slow calls.
`ServerSession.NotifyToolListChanged`, `NotifyPromptListChanged`, `NotifyResourceListChanged`, and `NotifyResourceUpdated` notify a single `2026-07-28` session's open `subscriptions/listen` streams.
`StreamableHTTPOptions.OnRequestSummary`, `HasParams`, and `Request.GetID` (`ClientRequest.ID` / `ServerRequest.ID`) expose request metadata to middleware and observability hooks.
`ClientSession.Discover`, `ParseURLElicitationRequiredError`, and `Annotations.SetPriority` / `HasPriority` (to serialize an explicit `0` priority).

## Behavior changes guarded by MCPGODEBUG

The new flags below revert the corresponding change (except `demotesessionlifecyclelog`, which is opt-in). All will be removed in **v1.11.0**; see [docs/mcpgodebug.md](https://github.com/modelcontextprotocol/go-sdk/blob/main/docs/mcpgodebug.md) for details.

- **`structuredcontentfloat64=1`** — decode numbers in `CallToolResult.StructuredContent` as `float64` instead of `json.Number` ([#1239](https://github.com/modelcontextprotocol/go-sdk/pull/1239)).
- **`disablepromptargsvalidation=1`** — call the prompt handler even when a required argument is missing instead of returning `-32602` ([#1297](https://github.com/modelcontextprotocol/go-sdk/pull/1297)).
- **`allowmissingclientparams=1`** — accept `elicitation/create`, `notifications/elicitation/complete`, and `notifications/resources/updated` with missing or `null` params ([#1315](https://github.com/modelcontextprotocol/go-sdk/pull/1315)).
- **`nopreinitinvalidrequest=1`** — refuse pre-`initialize` requests on legacy sessions with code `0` instead of `-32600` ([#1393](https://github.com/modelcontextprotocol/go-sdk/pull/1393)).
- **`nointernalerrorcode=1`** — send handler errors carrying no code with code `0` instead of `-32603` ([#1407](https://github.com/modelcontextprotocol/go-sdk/pull/1407)).
- **`fatalnewprotocolerrors=1`** — fail the streamable client connection when an independent `2026-07-28` request fails ([#1353](https://github.com/modelcontextprotocol/go-sdk/pull/1353)).
- **`followallredirects=1`** — follow cross-origin and method-changing HTTP redirects ([#1440](https://github.com/modelcontextprotocol/go-sdk/pull/1440)).
- **`demotesessionlifecyclelog=1`** *(opt-in)* — emit per-session lifecycle logs at debug level instead of info ([#1208](https://github.com/modelcontextprotocol/go-sdk/pull/1208)).

Options below were removed, according to plan:

- `customresnotfounderrcode`
- `hintomitempty`
- `allowsessionsinstateless`
- `nomethodnotfoundcodeinerror`
- `noprotocolerrorbody`
- `nowrapinvalidparams`
- `disablecompleteparamsvalidation`

The removal of `plaintextstatefulrejection` and `blockingcancelnotify`, added in v1.8.0, was postponed to **v1.10.0**.
