# cursor — Development environments for cloud agents

<p>To take engineering tasks from start to finish, agents need a development environment similar to the setup on your laptop: cloned repositories, installed dependencies, credentials for internal toolchains, and access to build systems.</p>
<p>This release introduces new tools for teams to configure development environments for their agents. Cursor also can use these tools to set up and maintain environments for you. Together, this makes it easier for teams to run fleets of parallelized agents that handle tasks from end-to-end, inside development environments you fully control.</p>
<h2>Multi-repo environments</h2>
<p>Cloud agents and automations now support multi-repo environments, building off our work on <a href="https://cursor.com/changelog/04-24-26#multi-root-workspaces-in-agents-window">multi-root workspaces</a>. You can configure a single environment with all the repositories an agent needs for its work, with re-use across sessions.</p>
<h2>Environment configuration as code</h2>
<p>To make it easier to change, debug, and review environment definitions, we have improved Dockerfile-based configuration.</p>
<p>This includes support for build secrets, making it easy to securely access private package registries directly from your Dockerfiles. Build secrets are scoped to the build step and aren&#39;t passed to the running agent&#39;s environment.</p>
<p><figure><img src="https://ptht05hbb1ssoooe.public.blob.vercel-storage.com/assets/blog/macbook-pro-14-234-1-.png" alt="Environment configuration as code" loading="lazy" /></figure></p>
<p>We&#39;ve also upgraded layer caching, so that only the updated layers of your image rebuild when you change the Dockerfile. Builds that hit the cache run 70% faster.</p>
<h2>Improved agent-led environment setup</h2>
<p>As Cursor configures your environment, it will ask you questions, flag missing credentials, and validate that your environment is set up properly.</p>
<p><figure><img src="https://ptht05hbb1ssoooe.public.blob.vercel-storage.com/assets/blog/improved-agent-setup.png" alt="Improved agent setup" loading="lazy" /></figure></p>
<p>Cursor will always show you the version of the environment your agent is running in. If your environment configuration fails, it will default to a base image with clear warning signs so that your cloud agents can keep running instead of immediately failing.</p>
<h2>Environment governance and security controls</h2>
<p>Every development environment now has its own version history that users can review and roll back. Admins can also restrict rollback permissions to admins only. An audit log captures every action team members take on environments, giving security teams full visibility into who changed what.</p>
<p>Egress and secrets can now be scoped at the development environment level. Secrets configured for one environment aren&#39;t accessible from any other.</p>
<p>Learn more about agent development environments in our <a href="https://cursor.com/blog/cloud-agent-development-environments">announcement</a> and <a href="https://cursor.com/docs/cloud-agent/setup">docs</a>.</p>
