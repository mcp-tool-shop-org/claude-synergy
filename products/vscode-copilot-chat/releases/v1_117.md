<h2 id="_bring-your-own-key-for-copilot-business-and-enterprise" data-needslink="_bring-your-own-key-for-copilot-business-and-enterprise">Bring your own key for Copilot Business and Enterprise</h2>
<p>Teams often need specific models for compliance, performance, or cost reasons, but switching between tools to use them slows developers down. Bring your own language model key (BYOK) lets Copilot Business and Enterprise users connect their own API keys for providers like OpenRouter, Ollama, Google, OpenAI, and more, so they can use those models directly in VS Code chat.</p>
<p>By default, BYOK is enabled and administrators can disable it with the <strong>Bring Your Own Language Model Key</strong> policy in the <a href="https://github.com/settings/copilot/features" class="external-link" target="_blank">Copilot policy settings</a> on GitHub.com. This gives administrators control over which model providers are available to their organization while keeping developers in their existing workflow.</p>
<p>After the policy is enabled, organization members can <a href="https://code.visualstudio.com/docs/copilot/customization/language-models#_bring-your-own-language-model-key">add models from built-in providers</a> or install language model provider extensions.</p>

<h3 id="_sort-agent-sessions-by-recent-activity" data-needslink="_sort-agent-sessions-by-recent-activity">Sort agent sessions by recent activity</h3>
<p>When you accumulate many agent sessions, finding the right one can be difficult. The <strong>Agent Sessions</strong> view supports sorting sessions by when they were created or last updated, so you can quickly pick up where you left off.</p>
<p><img src="/assets/updates/1_117/sort-by-filter.webp" alt="Screenshot of the Chat view with the filter context menu open, showing the sort by updated/created actions." loading="lazy"></p>
<h3 id="_system-notifications-for-background-terminal-commands" data-needslink="_system-notifications-for-background-terminal-commands">System notifications for background terminal commands</h3>
<p>When an agent runs a long-running terminal command in the background, it can be easy to lose track of its progress. These commands now surface as <strong>System notifications</strong> in the chat response, so you can monitor their status without switching to the terminal.</p>
<p><img src="/assets/updates/1_117/system-notification-terminal.webp" alt="Screenshot of a system notification appearing in the chat response." loading="lazy"></p>
<h2 id="_agent-experience" data-needslink="_agent-experience">Agent experience</h2>
<h3 id="_visual-studio-code-agents-insiders" data-needslink="_visual-studio-code-agents-insiders">Visual Studio Code Agents (Insiders)</h3>
<blockquote><p><strong>Note</strong>: The Visual Studio Code Agents app is currently in preview and only available when installing VS Code Insiders.</p>
</blockquote><p>The Visual Studio Code Agents app is a companion app that ships alongside VS Code Insiders, providing a focused, agent-native environment where you can run parallel sessions across repos, review diffs inline, and iterate on multi-step coding tasks. Introduced in <a href="https://code.visualstudio.com/updates/v1_115#_visual-studio-code-agents-preview">1.115</a>, the app continues to evolve based on feedback.</p>
<p>Updates in this release:</p>
<ul>
<li><strong>Create sub-sessions</strong>: Select <strong>+</strong> in the session title to spawn a sub-session from the current session. This is handy for starting additional work in context, such as parallel research or a code review, without losing your place in the parent session.</li>
<li><strong>Inline change rendering</strong>: Improvements to how changes are rendered inline make it easier to scan and compare diffs when the agent edits your code.</li>
<li><strong>Update experience</strong>: Improvements to the update flow across operating systems make it smoother to stay on the latest version.</li>
<li><strong>Theming, chat response, and UX polish</strong>: Continued refinements to theming, session list and response rendering, and overall UX across the app.</li>
</ul>
<p><img src="/assets/updates/1_117/Agents-117.webp" alt="Screenshot of the VS Code Agents - Insiders app with proposed changes." loading="lazy"></p>
<p>As in previous releases, you can open the app via the same methods:</p>
<ul>
<li>Launch <strong>Visual Studio Code Agents - Insiders</strong> from your Start menu or Applications folder in the OS.</li>
<li>Run <strong>Chat: Open Agents Application</strong> from the VS Code Insiders Command Palette.</li>
<li>Select <strong>Try out the new Agents app</strong> from the VS Code Insiders welcome page.</li>
</ul>
<h2 id="_terminal" data-needslink="_terminal">Terminal</h2>
<h3 id="_launch-copilot-cli-with-a-custom-terminal-profile" data-needslink="_launch-copilot-cli-with-a-custom-terminal-profile">Launch Copilot CLI with a custom terminal profile</h3>
<p>The Copilot CLI terminal profile can now be launched from the terminal panel, even when your default terminal profile is set to a non-default shell, such as <code>fish</code> on macOS or Linux, or Git Bash on Windows.</p>
<p>Previously, selecting <strong>GitHub Copilot CLI</strong> from the terminal profile picker in this configuration produced a <code>No terminal profile options provided for id 'copilot-cli'</code> error and the terminal failed to start.</p>
<h3 id="_terminal-title-for-agent-clis" data-needslink="_terminal-title-for-agent-clis">Terminal title for agent CLIs</h3>
<p>Agent CLIs like Copilot CLI, Claude Code, and Gemini CLI typically run as <code>node</code> processes, which meant the terminal title showed a generic <code>node</code> label. This made it hard to tell which agent was running in each terminal. The terminal now detects these agent CLIs as a distinct shell type and uses the OSC title sequence emitted by the CLI as the terminal title, so each terminal clearly identifies the agent it is hosting.</p>
<p><img src="/assets/updates/1_117/terminalAiCliTitle.webp" alt="Screenshot showing the terminal title reflecting the running agent CLI via its OSC title sequence." loading="lazy"></p>
<p>The improved detection covers Copilot CLI, Claude Code, and Gemini CLI on macOS, Linux, and Windows. Codex is not yet detected on macOS because it does not currently emit an OSC title sequence. This behavior is enabled by default and can be toggled with the <span class="setting"><span class="setting-dropdown" data-setting-id="terminal.integrated.tabs.allowAgentCliTitle">
