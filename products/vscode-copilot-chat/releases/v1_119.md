<h2 id="_agent-experience" data-needslink="_agent-experience">Agent experience</h2>
<h3 id="_sharing-browser-tabs-with-agents" data-needslink="_sharing-browser-tabs-with-agents">Sharing browser tabs with agents</h3>
<p>When agents can access a live browser, they validate changes in real time and iterate faster. For web development, an agent can edit code, reload the page, and confirm the fix in a single turn. For design workflows, the agent can compare rendered output against your intent and refine layout or styling on the fly. Get started with <a href="https://code.visualstudio.com/docs/copilot/guides/browser-agent-testing-guide">using the integrated browser with agents in VS Code</a>.</p>
<p>An agent does not automatically have access to the <a href="https://code.visualstudio.com/docs/debugtest/integrated-browser">integrated browser</a>. You need to explicitly share browser pages with the agent for it to interact with them. This helps keep sensitive data private.</p>
<p>In this release, we've added new ways to share browsers with an agent:</p>
<h4 id="_attach-browser-tabs-as-context" data-needslink="_attach-browser-tabs-as-context">Attach browser tabs as context</h4>
<p>Browser tabs can now be explicitly attached to the chat via typical entry points such as suggested context, context picker, and drag-and-drop actions.</p>
<p><img src="/assets/updates/1_119/browser-implicit-context.webp" alt="Screenshot showing an implicit context item in the chat for adding the open browser to the chat context." loading="lazy"></p>
<p>When a browser tab is attached, it enters a sharing state where the agent can read and interact with the page. Use the sharing button in the browser to stop sharing when you're done.</p>
<p><img src="/assets/updates/1_119/browser-share-button.webp" alt="Screenshot showing the Sharing with Agent button in the browser." loading="lazy"></p>
<h4 id="_agentsinitiated-requests-to-share-a-page" data-needslink="_agentsinitiated-requests-to-share-a-page">Agents-initiated requests to share a page</h4>
<p>Agents now have information about how many browser tabs you have open and are not shared. They can request to share an open tab when they need to interact with a page, and you can approve or deny the request in a prompt.</p>
<p>When an agent tries to open a new tab on the same domain as an existing, unshared tab, a prompt appears to ask if you want to reuse the existing tab. This aims to encourage tab reuse and reduce clutter.</p>
<p><img src="/assets/updates/1_119/browser-sharing-prompt.webp" alt="Screenshot showing a chat session where the user prompts to test the app in the browser and receives a prompt to share an existing tab." loading="lazy"></p>

<p>Copilot Chat agent sessions, including the local agent, the Copilot CLI background agent, and the Claude agent, now emit OpenTelemetry traces, metrics, and events that follow the <a href="https://github.com/open-telemetry/semantic-conventions/blob/main/docs/gen-ai/" class="external-link" target="_blank">GenAI semantic conventions</a>, so you can monitor agent behavior, latency, and token usage in any OTLP-compatible backend (for example, the <a href="https://aspire.dev/dashboard/standalone/" class="external-link" target="_blank">Aspire Dashboard</a>).</p>
<p>Each user request produces an <code>invoke_agent</code> root span (for example, <code>invoke_agent claude</code>) with nested <code>chat</code>, <code>execute_tool</code>, and <code>execute_hook</code> child spans. Subagent invocations are automatically parented to the calling agent's <code>execute_tool</code> span, giving you full visibility into the agent's work in a single connected trace. Spans report model and token usage, including cache read and cache creation breakdowns.</p>

<p>Todo lists help an agent stay on track during complex, multi-step tasks by giving it an explicit record of what's been done and what comes next. However, every tool call the main model makes to update a todo list costs tokens, and those costs add up across long sessions.</p>
<p>By offloading todo list management to a lightweight background agent, the main model can focus on the actual task while a smaller model keeps progress tracking in sync. This reduces overall token usage without sacrificing the guidance that keeps the agent focused.</p>
<p>When this setting is enabled, the background agent monitors main agent activity and updates the todo list to reflect completed and in-progress work. The main agent will not have the todo tool available, thus saving token cost for the conversations.</p>
<blockquote><p><strong>Note</strong>: If the todo tool is manually added to the chat request (for example with <code>#todo</code>), or a custom agent specifies it in its tool list, the background agent is overridden and does not run.</p>
</blockquote><p>This feature is disabled by default. To try it out, enable the <span class="setting"><span class="setting-dropdown" data-setting-id="github.copilot.chat.agent.backgroundTodoAgent.enabled">

<h2 id="_engineering" data-needslink="_engineering">Engineering</h2>
<h3 id="_finished-migrating-webviews-to-use-css-anchor-positioning" data-needslink="_finished-migrating-webviews-to-use-css-anchor-positioning">Finished migrating webviews to use CSS anchor positioning</h3>
<p>VS Code's webviews now use <a href="https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Anchor_positioning" class="external-link" target="_blank">anchor positioning</a> to position themselves visually in the workbench. This improves performance and makes relayouts more responsive, especially if there are many active webviews. It also let us fix some tricky, long-standing bugs, such as webviews going out of position on web when the workbench was moved.</p>
<p>Here's a typical relayout call for a single webview before the switch to anchor based positioning:</p>
<p><img src="/assets/updates/1_119/anchor-perf-before.webp" alt="Screenshot showing the performance trace of a relayout call before anchor-based positioning." loading="lazy"></p>
<p>Positioning the webview here was done using JS, which called <code>getBoundingClientRect</code>. This call ends up being relatively slow because it triggers browser style recalculations and relayouts.</p>
<p>By moving to anchor based positioning, the browser now handles positioning the webview for us based on the CSS.</p>
<p><img src="/assets/updates/1_119/anchor-perf-after.webp" alt="Screenshot showing the relayout performance after anchor-based positioning." loading="lazy"></p>
<h3 id="_typechecking-now-uses-typescript-7-for-faster-development-iteration" data-needslink="_typechecking-now-uses-typescript-7-for-faster-development-iteration">Typechecking now uses TypeScript 7 for faster development iteration</h3>
<p>Last iteration <a href="https://code.visualstudio.com/updates/v1_118#_faster-development-builds-with-typescript-7">we moved VS Code's main watch task to use TypeScript 7</a>. This iteration, we finished the migration to use TypeScript 7 for all built-in extensions and core code.</p>
<p>By migrating the Copilot extension to use TypeScript 7, we cut the typechecking time from 22 seconds to 4 seconds. These dramatic speedups enable both developers and agents to iterate more quickly in the VS Code codebase.</p>
