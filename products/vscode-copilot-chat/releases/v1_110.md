<h2 id="_agent-controls" data-needslink="_agent-controls">Agent controls</h2>
<p>Whether you are debugging an agent's behavior, tweaking approval flows, or handing work off to a background process, these updates give you more visibility and control over how agents run.</p>
<h3 id="_background-agents" data-needslink="_background-agents">Background agents</h3>
<p>With <a href="https://code.visualstudio.com/docs/copilot/agents/copilot-cli">background agents</a>, you can hand off tasks to Copilot CLI, while still keeping track of them in VS Code. We have made several improvements to align the capabilities and experience of background agents with local and cloud agents.</p>
<ul>
<li>
<p><strong>Context compaction</strong>: Copilot automatically compacts the conversation history when the context window reaches its limit. You can now also manually trigger compaction for background agents with the <code>/compact</code> slash command.</p>
</li>
<li>
<p><strong>Use /slash commands</strong>: chat customization options like <a href="https://code.visualstudio.com/docs/copilot/customization/reusable-prompts">prompt files</a>, <a href="https://code.visualstudio.com/docs/copilot/customization/hooks">hooks</a>, and <a href="https://code.visualstudio.com/docs/copilot/customization/agent-skills">skills</a> are now also available in background agent sessions as slash commands.</p>
<p><img src="/assets/updates/1_110/background-agent-slash-commands.png" alt="Screenshot showing slash commands for background agents." loading="lazy"></p>
</li>
<li>
<p><strong>Rename background agent sessions</strong>: you can now rename your background agent sessions to keep track of them more easily.</p>
<p><img src="/assets/updates/1_110/background-agent-rename-session.png" alt="Screenshot showing support for renaming background agent sessions." loading="lazy"></p>
</li>
</ul>
<h3 id="_claude-agents" data-needslink="_claude-agents">Claude agents</h3>
<p>Last month, we added <a href="https://code.visualstudio.com/updates/v1_109#_claude-agent-preview">Claude agents</a>, enabling you to interact with the Claude Agent SDK using Claude models included in your GitHub Copilot subscription.</p>
<p>This month, we've expanded this experience with new features and improvements:</p>
<ul>
<li>
<p><strong>Steering and queuing</strong> to let you send follow-up messages mid-conversation to alter the agent's approach or to queue up additional requests.</p>
</li>
<li>
<p><strong>Session renaming</strong></p>
<p><img src="/assets/updates/1_110/claude-session-rename.png" alt="Screenshot of the session rename action on the chat session item." loading="lazy"></p>
</li>
<li>
<p><strong>Context window rendering with compaction</strong></p>
<p><img src="/assets/updates/1_110/claude-context-window.png" alt="Screenshot of the context window control." loading="lazy"></p>
</li>
<li>
<p><strong>Additional slash commands</strong></p>
<ul>
<li><code>/compact</code> for on-demand compaction</li>
<li><code>/agents</code> to manage custom agents</li>
<li><code>/hooks</code> to manage Claude hooks</li>
</ul>
</li>
<li>
<p><strong>Add the <code>getDiagnostics</code> tool</strong> to let the agent access editor and workspace problems</p>
</li>
<li>
<p><strong>Significant performance improvements</strong></p>
</li>
</ul>
<p>More improvements are planned. Share your feedback <a href="https://github.com/microsoft/vscode" class="external-link" target="_blank">on GitHub</a>!</p>
<h3 id="_agent-debug-panel-preview" data-needslink="_agent-debug-panel-preview">Agent Debug panel (Preview)</h3>
<p>With different agent customizations like hooks, skills, and custom agents, it can sometimes be difficult to understand what happens when you send a message to an agent. The Agent Debug panel gives you deeper visibility into your chat sessions and how your chat customizations are loaded.</p>
<p>The Agent Debug panel shows chat events in real time, including chat customization events, system prompts, tool calls, and more. You can see exactly which prompt files, skills, hooks, and other customizations are loaded for a session, making it easier to understand and troubleshoot your agent configuration. This replaces the old <strong>Diagnostics</strong> chat action with a richer, more detailed view.</p>
<p><img src="/assets/updates/1_110/agent-logs.png" alt="Screenshot showing the Agent Debug panel with a list of chat events and a chart view." loading="lazy"></p>
<p>Open the panel from the Command Palette with <strong>Developer: Open Agent Debug Panel</strong>, or select the gear icon at the top of the Chat view and choose <strong>View Agent Logs</strong>.</p>
<p>The panel also includes a chart view that displays a visual hierarchy of events, so you can quickly understand the structure and sequence of what happens during a chat session.</p>
<p><img src="/assets/updates/1_110/agent-flow-chart.png" alt="Screenshot showing the flow chart view in the Agent Debug panel." loading="lazy"></p>
<p>This experience is still in preview, so try it out and share your feedback!</p>
<blockquote><p><strong>Note</strong>: The Agent Debug panel is currently only available for local chat sessions. Log data is not persisted, so you can only view logs for chat sessions from your current VS Code session.</p>
</blockquote><h3 id="_slash-commands-for-enabling-auto-approval" data-needslink="_slash-commands-for-enabling-auto-approval">Slash commands for enabling auto approval</h3>
<p>You can now toggle <a href="https://code.visualstudio.com/docs/copilot/chat/chat-agent-mode#_auto-approve-tools">global auto approve</a> directly from the chat input using slash commands, without navigating to settings:</p>
<ul>
<li><code>/autoApprove</code> enables global auto approve for all tools</li>
<li><code>/disableAutoApprove</code> disables global auto approve</li>
</ul>
<p><code>/yolo</code> and <code>/disableYolo</code> are aliases for the same commands.</p>
<blockquote><p><strong>CAUTION</strong>: Global auto approve skips all tool confirmation prompts, letting the agent run tools and terminal commands without waiting for your approval. This can speed up longer, multi-step tasks but means you won't have the opportunity to cancel potentially destructive actions. Make sure you understand the <a href="https://code.visualstudio.com/docs/copilot/security">security implications</a> before enabling it and consider using <a href="https://code.visualstudio.com/docs/copilot/agents/agent-tools#_sandbox-terminal-commands-experimental">terminal sandboxing</a> for additional protection.</p>

<h3 id="_ask-questions-tool" data-needslink="_ask-questions-tool">Ask questions tool</h3>
<p>The <code>askQuestions</code> tool, which presents a question carousel UI during chat interactions, has been moved into VS Code core. This improves reliability when canceling requests and enables the tool to work consistently across different contexts, including subagents.</p>
<p><img src="/assets/updates/1_110/ask-questions-tool.png" alt="Screenshot showing the ask questions tool with a carousel of questions and a question input box." loading="lazy"></p>
<p>When the carousel is active, you can now send a steering message without needing to reply to or dismiss pending questions first. This allows you to redirect the agent's response on the fly, even in the middle of a question sequence. Use the keyboard to navigate between questions with <span class="dynamic-keybinding" data-commandid="workbench.action.chat.nextQuestion" data-osx="⌥N" data-win="Alt+N" data-linux="Alt+N"><span class="keybinding">⌥N</span> (Windows, Linux <span class="keybinding">Alt+N</span>)</span> (next) and <span class="dynamic-keybinding" data-commandid="workbench.action.chat.previousQuestion" data-osx="⌥P" data-win="Alt+P" data-linux="Alt+P"><span class="keybinding">⌥P</span> (Windows, Linux <span class="keybinding">Alt+P</span>)</span> (previous).</p>
<h3 id="_prevent-autosuspend-during-chat" data-needslink="_prevent-autosuspend-during-chat">Prevent auto-suspend during chat</h3>
<p>VS Code now asks the operating system not to automatically suspend the machine while a chat request is running. You can step away from your computer without worrying about interrupting the agent's response.</p>
<p>Note that closing the lid of an unplugged laptop still triggers suspension.</p>

<h3 id="_create-agent-customizations-from-chat" data-needslink="_create-agent-customizations-from-chat">Create agent customizations from chat</h3>
<p>You can now generate <a href="https://code.visualstudio.com/docs/copilot/customization">agent customization</a> files directly from a chat conversation by using new <code>/create-*</code> slash commands in agent mode:</p>
<ul>
<li><code>/create-prompt</code>: generate a reusable <a href="https://code.visualstudio.com/docs/copilot/customization/prompt-files">prompt</a> file</li>
<li><code>/create-instruction</code>: generate an <a href="https://code.visualstudio.com/docs/copilot/customization/custom-instructions">instruction</a> file for project conventions</li>
<li><code>/create-skill</code>: extract a multi-step workflow into a <a href="https://code.visualstudio.com/docs/copilot/customization/agent-skills">skill</a> package</li>
<li><code>/create-agent</code>: create a specialized <a href="https://code.visualstudio.com/docs/copilot/customization/custom-agents">custom agent</a> persona</li>
<li><code>/create-hook</code>: create a <a href="https://code.visualstudio.com/docs/copilot/customization/hooks">hook</a> configuration for lifecycle automation</li>
</ul>
<p>Each command guides you through the creation process and lets you choose between user-level (account-wide) or workspace-level (project-specific) storage.</p>
<p>The commands can also extract patterns from an ongoing conversation. For example, after debugging an issue over several turns, use <code>/create-skill</code> to capture the procedure as a reusable skill, or <code>/create-instruction</code> to turn corrections into project conventions.</p>
<p>You don't need to remember the exact slash command. You can also use natural language, such as "save this workflow as a skill" or "extract an instruction from this", and the agent recognizes your intent and starts the correct creation flow.</p>
<p>The same generation options are available from the quick pick menus for prompts, instructions, skills, and agents, indicated by a sparkle icon.</p>

<h2 id="_smarter-sessions" data-needslink="_smarter-sessions">Smarter sessions</h2>
<p>Long-running and multi-turn tasks work better when the agent remembers context, delegates research efficiently, and keeps your inline edits in sync. These improvements make sessions more resilient and context-aware.</p>
<h3 id="_session-memory-for-plans" data-needslink="_session-memory-for-plans">Session memory for plans</h3>
<p>Plans created by the Plan agent now persist to <a href="https://code.visualstudio.com/docs/copilot/chat/chat-agent-mode#_session-memory">session memory</a> and stay available across conversation turns. When you ask for refinements, the agent builds on the existing plan instead of starting from scratch.</p>
<p>The plan is also recalled after unrelated messages in the same session, so you can return to a plan without repeating context. During longer implementation work, the plan remains accessible in memory even when older conversation history is compacted to free up context space.</p>
<h3 id="_context-compaction" data-needslink="_context-compaction">Context compaction</h3>
<p>As a conversation grows, the accumulated messages and context can fill up the model's context window. Context compaction summarizes the conversation history to free up space, so you can continue working in the same session without losing important details.</p>
<p>VS Code automatically compacts the conversation when the context window reaches its limit, but you can also trigger compaction manually. Manual compaction is available for local, background, and Claude agent sessions. To manually compact, use one of the following methods:</p>
<ul>
<li>
<p>Type <code>/compact</code> in the chat input field. Optionally, add custom instructions after the command to guide how the summary is generated, for example <code>/compact focus on the database schema decisions</code>.</p>
</li>
<li>
<p>Select the context window control in the chat input box, and then select <strong>Compact Conversation</strong>.</p>
</li>
</ul>
<p><img src="/assets/updates/1_110/context-compaction.png" alt="Screenshot showing the context window control and the compact option." loading="lazy"></p>
<p>Learn more about <a href="https://code.visualstudio.com/docs/copilot/chat/copilot-chat-context#_context-compaction">context compaction</a> in the documentation.</p>

<h2 id="_languages" data-needslink="_languages">Languages</h2>
<h3 id="_unified-javascript-and-typescript-settings" data-needslink="_unified-javascript-and-typescript-settings">Unified JavaScript and TypeScript settings</h3>
<p>To prepare for the <a href="https://devblogs.microsoft.com/typescript/progress-on-typescript-7-december-2025/" class="external-link" target="_blank">upcoming TypeScript 6.0 and 7.0 releases</a>, we've consolidated and cleaned up our built-in JavaScript and TypeScript setting IDs. Previously many of these settings had duplicate <code>javascript.*</code> and <code>typescript.*</code> versions. This is because these settings are from before we added <a href="https://code.visualstudio.com/docs/getstarted/tips-and-tricks#_language-specific-settings">a standard approach to language-specific settings</a>. Some of the settings names were also inconsistent.</p>
<p>Now all of these settings have been moved under the <code>js/ts.*</code> prefix. This means that by default you only need to update a single setting value to change the behavior in both JavaScript and TypeScript files. You can use <a href="https://code.visualstudio.com/docs/getstarted/tips-and-tricks#_language-specific-settings">language-specific settings</a> if you want different behavior in JavaScript and TypeScript files.</p>
<p>For example, instead of setting:</p>
<pre class="shiki" data-lang="json" shiki-themes="" dark-plus="" light-plus"="" style="--shiki-dark:#D4D4D4;--shiki-light:#000000;--shiki-dark-bg:#1E1E1E;--shiki-light-bg:#FFFFFF" tabindex="0"><code><span class="line"><span style="--shiki-dark:#CE9178;--shiki-light:#A31515">"javascript.format.enable"</span><span style="--shiki-dark:#D4D4D4;--shiki-light:#000000">: </span><span style="--shiki-dark:#569CD6;--shiki-light:#0000FF">false</span><span style="--shiki-dark:#D4D4D4;--shiki-light:#000000">,</span></span>
<span class="line"><span style="--shiki-dark:#CE9178;--shiki-light:#A31515">"typescript.format.enable"</span><span style="--shiki-dark:#D4D4D4;--shiki-light:#000000">: </span><span style="--shiki-dark:#569CD6;--shiki-light:#0000FF">true</span></span>
<span class="line"></span></code></pre>
<p>You can now use language-specific overrides with the unified setting:</p>
<pre class="shiki" data-lang="json" shiki-themes="" dark-plus="" light-plus"="" style="--shiki-dark:#D4D4D4;--shiki-light:#000000;--shiki-dark-bg:#1E1E1E;--shiki-light-bg:#FFFFFF" tabindex="0"><code><span class="line"><span style="--shiki-dark:#CE9178;--shiki-light:#A31515">"[javascript][javascriptreact]"</span><span style="--shiki-dark:#D4D4D4;--shiki-light:#000000">: {</span></span>
<span class="line"><span style="--shiki-dark:#9CDCFE;--shiki-light:#0451A5">    "js/ts.format.enabled"</span><span style="--shiki-dark:#D4D4D4;--shiki-light:#000000">: </span><span style="--shiki-dark:#569CD6;--shiki-light:#0000FF">false</span></span>
<span class="line"><span style="--shiki-dark:#D4D4D4;--shiki-light:#000000">},</span></span>
<span class="line"><span style="--shiki-dark:#CE9178;--shiki-light:#A31515">"[typescript][typescriptreact]"</span><span style="--shiki-dark:#D4D4D4;--shiki-light:#000000">: {</span></span>

<span class="line"></span></code></pre>
<p>You can also customize the settings for JSX files only by using <code>[javascriptreact]</code>.</p>
<p>The old <code>javascript.*</code> and <code>typescript.*</code> settings continue to work but are now marked as deprecated and will be overridden if the new unified <code>js/ts</code> settings are set.</p>
<p>We understand this is a big change, however we think it's the right one for the long term quality of VS Code. The unified settings make it easier to change JavaScript and TypeScript settings, and also enable support for modern options such as language-specific settings.</p>
<h3 id="_python" data-needslink="_python">Python</h3>
<h4 id="_python-environments-extension-rolling-out-to-all-users" data-needslink="_python-environments-extension-rolling-out-to-all-users">Python Environments extension rolling out to all users</h4>
<p>The <a href="https://marketplace.visualstudio.com/items?itemName=ms-python.vscode-python-envs" class="external-link" target="_blank">Python Environments extension</a> is now rolling out to all users after a year in preview. The extension brings a unified interface for managing Python environments, packages, and interpreters directly in VS Code, regardless of whether you use venv, conda, pyenv, poetry, or pipenv.</p>
<p>Key capabilities include:</p>
<ul>
<li><strong>Quick Create</strong>: Create an environment with a single click using your default manager and the latest Python version</li>
<li><strong>Python Projects</strong>: Assign environments to specific folders for monorepos and multi-service workspaces</li>
<li><strong>uv integration</strong>: Faster environment creation and package installation when <a href="https://github.com/astral-sh/uv" class="external-link" target="_blank">uv</a> is installed</li>
<li><strong>Built-in package management</strong>: Search, install, and uninstall packages from the Environment Managers view</li>
<li><strong>Portable settings</strong>: Environment configurations use manager types instead of hardcoded paths, making <code>settings.json</code> portable across machines</li>
</ul>
<p>You can expect the extension to be enabled automatically over the next few weeks, or you can opt in immediately with the <code>python.useEnvsExtension</code> setting.</p>
<p>For more details, read the <a href="https://devblogs.microsoft.com/python/python-in-visual-studio-code-february-2026-release/" class="external-link" target="_blank">announcement blog post</a> or see the <a href="https://code.visualstudio.com/docs/python/environments">Python environments documentation</a>.</p>

<h2 id="_engineering" data-needslink="_engineering">Engineering</h2>
<h3 id="_typescriptgo-for-vs-code-engineering" data-needslink="_typescriptgo-for-vs-code-engineering">TypeScript-Go for VS Code engineering</h3>
<p>We've continued adopting <a href="https://github.com/microsoft/typescript-go" class="external-link" target="_blank">TypeScript-Go (tsgo)</a> for development work in the <code>vscode</code> repo.</p>
<p>As of this iteration, we default the <code>vscode</code> workspace to using TSGo for development. We've already noticed performance improvements from this, and it also helps us test TSGo's language tooling.</p>
<p>We now also use <a href="https://github.com/microsoft/typescript-go" class="external-link" target="_blank">TypeScript-Go (tsgo)</a> to compile VS Code's built-in extensions during development. As a result, each of our built-in extensions is now built and fully typechecked in under a second.</p>
<h3 id="_extension-bundling-with-esbuild" data-needslink="_extension-bundling-with-esbuild">Extension bundling with esbuild</h3>
<p>We've migrated most of our built-in extensions to use esbuild instead of webpack for bundling. Esbuild is used for both bundling the desktop and web versions of these extensions.</p>
<p>This migration has both simplified and sped up our builds. There are only a handful of extensions left to migrate and we hope to finish this work in March.</p>
