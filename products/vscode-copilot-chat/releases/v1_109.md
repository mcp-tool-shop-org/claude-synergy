                <h1>January 2026 (version 1.109)</h1>
<p><em>Release date: February 4, 2026</em></p>
<p><strong>Update 1.109.1</strong>: The update addresses these <a href="https://github.com/microsoft/vscode/issues?q=is%3Aissue+is%3Aclosed+milestone%3A%22January+2026+Recovery+1%22+" class="external-link" target="_blank">security issues</a>.</p>
<p><strong>Update 1.109.2</strong>: The update addresses an <a href="https://github.com/microsoft/vscode/issues/294530#issuecomment-3891109505" class="external-link" target="_blank">issue with chat</a>.</p>
<p><strong>Update 1.109.3</strong>: The update addresses these <a href="https://github.com/microsoft/vscode/issues?q=is%3Aissue+is%3Aclosed+milestone%3A%22January+2026+Recovery+3%22+" class="external-link" target="_blank">issues</a> and introduces several notable features:</p>
<ul>
<li><a href="#_message-steering-and-queueing-experimental">Message steering and queueing</a>: send follow-up messages while a request is still running</li>
<li><a href="#_agent-hooks-preview">Agent hooks</a>: run custom shell commands at key agent lifecycle points</li>
<li><a href="#_claude-compatibility">Claude compatibility</a>: reuse your Claude configuration files directly in VS Code</li>
<li><a href="#_use-skills-as-slash-commands">Use skills as slash commands</a>: invoke agent skills on demand from chat</li>
</ul>
<p><strong>Update 1.109.4</strong>: The update addresses these <a href="https://github.com/microsoft/vscode/issues?q=is%3Aissue+is%3Aclosed+milestone%3A%22January+2026+Recovery+4%22+" class="external-link" target="_blank">issues</a>.</p>
<p><strong>Update 1.109.5</strong>: The update addresses these <a href="https://github.com/microsoft/vscode/issues?q=is%3Aissue+is%3Aclosed+milestone%3A%22January+2026+Recovery+5%22+" class="external-link" target="_blank">issues</a> and adds these features to improve <a href="#_background-agents">background agents</a>:</p>
<ul>
<li>Support for slash commands, including prompt files, hooks, and skills</li>
<li>The ability to rename background agent sessions</li>
<li>Kitty keyboard support is now available to all users</li>
</ul>

<p><strong>Update 1.109.3</strong>: When working on longer tasks, you often think of the next task before the current or notice the agent heading in the wrong direction. Previously, you had to wait for a response to complete or cancel it entirely. Now you can send follow-up messages while a request is still running.</p>
<p><img src="/assets/updates/1_109/send-dropdown.png" alt="Screenshot showing the Send button dropdown with options to Add to Queue, Steer with Message, and Stop and Send." loading="lazy"></p>
<p>While a request is in progress, the <strong>Send</strong> button changes to a dropdown with three options:</p>
<ul>
<li><strong>Add to Queue</strong>: your message waits and sends automatically after the current response completes.</li>
<li><strong>Steer with Message</strong>: signals the current request to yield after finishing the active tool execution, then processes your new message immediately. Use this to redirect the agent when it's heading in the wrong direction.</li>
<li><strong>Stop and Send</strong>: cancels the current request entirely and sends your new message immediately.</li>
</ul>
<p>When you have multiple pending messages, drag and drop them to change the order in which they are processed.</p>
<p>Use <span class="setting"><span class="setting-dropdown" data-setting-id="chat.requestQueuing.defaultAction">

Unlike instructions or custom prompts that guide agent behavior, hooks run your code deterministically with guaranteed outcomes. Use them to enforce security policies, automate code quality checks, create audit trails, or inject project-specific context.</p>

<h3 id="_claude-compatibility" data-needslink="_claude-compatibility">Claude compatibility</h3>
<p>If you use both VS Code and Claude, you no longer need to maintain separate configuration files. VS Code now reads Claude configuration files directly, so your agents, skills, instructions, and hooks work across both tools without duplication.</p>
<p>VS Code detects the following Claude file locations:</p>
<ul>
<li><strong>Instructions</strong>: <code>CLAUDE.md</code> files in your workspace root, <code>.claude/CLAUDE.md</code>, and <code>~/.claude/CLAUDE.md</code>. VS Code also reads instruction files from the <code>.claude/rules</code> folder. See <a href="https://code.visualstudio.com/docs/copilot/customization/custom-instructions#_use-a-claudemd-file">Custom Instructions</a> for details.</li>
<li><strong>Agents</strong>: <code>.md</code> files in the <code>.claude/agents</code> folder, following the Claude sub-agents format. See <a href="#_custom-agent-file-locations">Custom agent file locations</a> for details.</li>
<li><strong>Skills</strong>: Skill definitions in <code>.claude/skills</code> and <code>~/.claude/skills</code> folders. See <a href="#_agent-skills-are-generally-available">Agent Skills</a> for details.</li>
<li><strong>Hooks</strong>: Hook configurations in <code>.claude/settings.json</code> and <code>~/.claude/settings.json</code>. See <a href="#_agent-hooks-preview">Agent hooks</a> for details.</li>

<h3 id="_agent-orchestration" data-needslink="_agent-orchestration">Agent orchestration</h3>
<p>Agent orchestration is a powerful pattern for building complex AI workflows where multiple specialized agents collaborate to achieve a common goal. Instead of relying on a single agent to handle everything, orchestration distributes work across purpose-built agents, each optimized for a specific role like planning, implementation, code review, or research.</p>
<p>This approach provides several key benefits:</p>
<ul>
<li><strong>Context efficiency</strong>: Each subagent operates in its own dedicated context window, preventing context overflow</li>
<li><strong>Specialization</strong>: Different agents can use different models optimized for their task</li>
<li><strong>Parallel execution</strong>: Independent tasks can run in parallel across multiple subagents</li>
</ul>
<p><img src="/assets/updates/1_109/agent-orchestration-diagram.png" alt="Diagram showing an orchestration system with multiple specialized agents collaborating to complete a task." loading="lazy">
<em>Image source <a href="https://github.com/ShepAlderson/copilot-orchestra" class="external-link" target="_blank">https://github.com/ShepAlderson/copilot-orchestra</a> by <a href="https://github.com/ShepAlderson" class="external-link" target="_blank">@ShepAlderson</a></em></p>
<p>VS Code has all the building blocks for setting up your agent orchestration flow with <a href="https://code.visualstudio.com/docs/copilot/customization/custom-agents">custom agents</a>, <a href="https://code.visualstudio.com/docs/copilot/agents/subagents">subagents</a>, and extra control over <a href="#_control-how-custom-agents-are-invoked">how agents are invoked</a>.</p>
<p>The community has created excellent examples of agent orchestration systems that you can use directly or adapt to your needs:</p>
<ul>
<li>
<p><a href="https://github.com/ShepAlderson/copilot-orchestra" class="external-link" target="_blank">Copilot Orchestra</a> - A multi-agent system with a "Conductor" that orchestrates planning, implementation, and code review subagents through a complete development cycle</p>
</li>
<li>
<p><a href="https://github.com/bigguy345/Github-Copilot-Atlas" class="external-link" target="_blank">GitHub Copilot Atlas</a> - An extended orchestration system with specialized agents like "Prometheus" for planning, "Oracle" for research, "Sisyphus" for implementation, and "Explorer" for rapid codebase discovery</p>
</li>
</ul>

<h3 id="_terminal-tool-lifecycle-improvements" data-needslink="_terminal-tool-lifecycle-improvements">Terminal tool lifecycle improvements</h3>
<p>Several changes were made in this release to help solve problems around incorrect background terminal behavior:</p>
<ul>
<li>
<p>You can now manually push a terminal tool call to the background, freeing up the agent to continue with other work.</p>
<p><img src="/assets/updates/1_109/terminal-tool-continue-in-background.png" alt="Screenshot showing the button with the play icon that allows the agent to continue with that command running in the background." loading="lazy"></p>
</li>
<li>
<p>A new <code>timeout</code> property is required to be filled in by the agent when a call to the terminal tool is made, where 0 means no timeout. This gives an extra escape to return control back to the agent when something unexpected happens.</p>
</li>
<li>
<p>The new <code>awaitTerminal</code> tool gives the agent the ability to wait for background terminals to complete, this also requires the <code>timeout</code> property. Provided the model leverages this tool, the expectation is that it prevents <code>echo "successful"</code> and <code>sleep n</code> calls that were previously used to wait for background commands to finish.</p>
</li>
<li>
<p>The new <code>killTerminal</code> tool gives the agent the ability to kill background terminals to clean up after itself. This aims to prevent how the agent would sometimes kill processes to achieve the same thing in a roundabout way, for example when it wants to stop an old in-progress server command.</p>
</li>
<li>
<p>Several instruction changes around how the current working directory works since the active non-background terminal always persists the current working directory, whereas background terminals always start in the workspace directory.</p>
</li>
</ul>

<p>You can now create toggle buttons in quick inputs by setting the <code>toggle</code> property to <code>{ checked: boolean }</code> on a <code>QuickInputButton</code>. This is useful for actions that have two states, such as enabling or disabling a feature, applying filters, or switching modes.</p>
<h3 id="_proposed-apis" data-needslink="_proposed-apis">Proposed APIs</h3>
<h3 id="_chat-model-provider-configuration" data-needslink="_chat-model-provider-configuration">Chat Model Provider Configuration</h3>
<p>We've introduced a new proposed API that enables chat model provider extensions to declare their configuration requirements through the <code>languageModelChatProviders</code> contribution point. With this API, VS Code provides a built-in UI for users to enter their configuration (such as API keys and model settings), and passes this configuration to the extension via the API.</p>
<p>This approach will replace the existing <code>managementCommand</code> property in future releases. Instead of extensions implementing their own configuration UI through a command, they can now declare their configuration schema and let VS Code handle the user experience.</p>
<p>VS Code provides native UI controls for primitive property types such as <code>string</code>, <code>number</code>, and <code>boolean</code>. For complex types like <code>array</code> and <code>object</code>, VS Code opens the corresponding configuration file and allows users to enter the configuration directly in the JSON editor with full schema validation and IntelliSense support. See <a href="#_language-models-editor">Language Models editor</a> for details on the configuration experience.</p>

<h3 id="_chat-output-renderer-api-updates" data-needslink="_chat-output-renderer-api-updates">Chat output renderer API updates</h3>
<p>We've continued working on the chat output renderer API. This API lets extensions render custom interactive content in chat responses using webviews.</p>
<p>In addition to a number of bug fixes, we now also pass renderers as <code>ChatOutputWebview</code> instead of only passing a <code>Webview</code> directly. This lets extensions monitor when the webview is disposed of, so they can clean up any associated resources. The webview will be recreated by VS Code when it becomes visible again.</p>
<p>Check out the <a href="https://github.com/microsoft/vscode-extension-samples/tree/main/chat-output-renderer-sample" class="external-link" target="_blank">chat output renderer sample extension</a> for details on how to use this API.</p>
<h3 id="_portable-mode-detection" data-needslink="_portable-mode-detection">Portable mode detection</h3>
<p>A new <code>env.isAppPortable</code> property lets extensions detect whether VS Code is running in <a href="https://code.visualstudio.com/docs/editor/portable">portable mode</a>. Portable mode is enabled when the application runs from a folder containing a <code>data</code> directory, allowing for self-contained installations that don't leave traces on the host system.</p>

<h2 id="_engineering" data-needslink="_engineering">Engineering</h2>
<h3 id="_dmg-image-for-macos" data-needslink="_dmg-image-for-macos">DMG image for macOS</h3>
<p>VS Code now offers DMG images for macOS to provide a native drag-and-drop installation experience. The images are available for all supported architectures from the <a href="https://code.visualstudio.com/download">VS Code website</a>.</p>
<p><img src="/assets/updates/1_109/macos-dmg-installer.png" alt="Screenshot showing the macOS DMG image mounted." loading="lazy"></p>
<h3 id="_windows-11-context-menu-integration" data-needslink="_windows-11-context-menu-integration">Windows 11 context menu integration</h3>
<p>When installing VS Code with context menu support, right-click on a file or folder in Windows 11 File Explorer will now add an entry in the top level context menu, eliminating the need to select <code>Show more options</code> to access VS Code. Both user and system installers support this new entry.</p>
<p><img src="/assets/updates/1_109/win11-context-menu.png" alt="Screenshot showing VS Code in the Windows 11 context menu." loading="lazy"></p>
<h3 id="_redesigned-installation-layout-for-windows" data-needslink="_redesigned-installation-layout-for-windows">Redesigned installation layout for Windows</h3>
<p>We redesigned the installation layout on Windows to address long-standing reliability issues related to in-app updates. Most notably, the previous version performed atomic file replacement operations that could fail if they were interrupted by system shutdown, user intervention, or other unexpected events, sometimes leaving VS Code in a broken state. The new implementation takes inspiration from <a href="https://github.com/microsoft/vscode/issues/249239" class="external-link" target="_blank">Chromium's update client</a> and uses versioned package paths.</p>
<h3 id="_avoid-consecutive-updates-for-macos" data-needslink="_avoid-consecutive-updates-for-macos">Avoid consecutive updates for macOS</h3>
<p>If a new update becomes available while the previous update is still pending to be applied, VS Code now invalidates the previous update and proceeds with applying the new one, instead of forcing the user to restart the application twice.</p>
<h3 id="_copilot-extension-deprecated" data-needslink="_copilot-extension-deprecated">Copilot extension deprecated</h3>
<p>The GitHub Copilot extension has been deprecated. All AI functionality is now fully served by the GitHub Copilot Chat extension. When you update VS Code, the deprecated Copilot extension is automatically uninstalled, while the Copilot Chat extension remains installed and provides the complete Copilot experience.</p>
<p><img src="/assets/updates/1_109/copilot-extension-deprecated.png" alt="Screenshot showing the deprecated Copilot extension and the active Copilot Chat extension." loading="lazy"></p>
<h3 id="_consume-codicons-from-npm-package" data-needslink="_consume-codicons-from-npm-package">Consume codicons from npm package</h3>
<p>Codicons are now consumed through the <code>@vscode/codicons</code> npm package instead of being bundled directly in the VS Code repository and are incorporated as part of the build process.</p>
