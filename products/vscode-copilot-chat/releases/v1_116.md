<h3 id="_configure-thinking-effort-in-copilot-cli" data-needslink="_configure-thinking-effort-in-copilot-cli">Configure thinking effort in Copilot CLI</h3>
<p>Similar to local agent sessions, you can now configure the thinking effort for reasoning models in Copilot CLI sessions with the language model picker. Thinking effort controls how much reasoning the model applies to each request, which can help balance response quality and latency based on your needs.</p>
<p>Choose a reasoning model in the picker and select the arrow to reveal the available effort levels. The available effort levels might vary by model. Non-reasoning models do not show the submenu.</p>

<h2 id="_terminal-tools" data-needslink="_terminal-tools">Terminal tools</h2>
<h3 id="_foreground-terminal-support-for-agent-tools" data-needslink="_foreground-terminal-support-for-agent-tools">Foreground terminal support for agent tools</h3>
<p>The <code>send_to_terminal</code> and <code>get_terminal_output</code> agent tools now also work with foreground terminals and not just background terminals that were created by the agent. This means that the agent can read output from and send input to any terminal visible in the terminal panel, such as a running REPL or an interactive script.</p>
<h3 id="_terminal-input-improvements" data-needslink="_terminal-input-improvements">Terminal input improvements</h3>
<p>This release includes several improvements to the experience for terminal input in agent sessions:</p>
<ul>
<li>
<p><strong>Detect terminal input</strong>: The LLM-based prompt-for-input detection is removed. Previously, every terminal output chunk triggered an extra LLM call to classify whether the terminal was waiting for input, which added latency and used extra tokens. The agent now handles terminal input directly via <code>send_to_terminal</code> and uses the question carousel to defer to you when needed.</p>
</li>
<li>
<p><strong>Progress messages</strong>: When the agent sends answers to the terminal, the progress message now shows which question is being answered, for example: <code>Sending "my-project" to terminal (replying to: What is your project name?)</code>.</p>
</li>
<li>
<p><strong>Focus Terminal</strong>: When the agent needs terminal input, like when prompting for a password or an interactive installer like <code>npm init</code>, the question carousel now includes a <strong>Focus Terminal</strong> button. Select it to focus the relevant terminal and type your response directly. If you start typing in the terminal while the carousel is open, it automatically dismisses and informs the agent that you are handling the input directly.</p>
</li>
</ul>
<p><video src="/assets/updates/1_116/terminal-prompt-for-input.mp4" title="Video showing the question carousel for terminal input with a Focus Terminal button." autoplay="" loop="" controls="" muted=""></video></p>

<h2 id="_chat-ux" data-needslink="_chat-ux">Chat UX</h2>
<p>This release includes a few UX improvements to chat:</p>
<ul>
<li>
<p><strong>Diffs in the top level</strong>: Code diffs now render directly in the chat conversation, so you can review proposed changes without switching context to a separate diff view.</p>
<p><img src="/assets/updates/1_116/chat-rendering-improvements.webp" alt="Screenshot showing improved chat rendering with streaming updates and progress indicators." loading="lazy"></p>
</li>
<li>
<p><strong>Rendering performance</strong>: Chat responses should now render faster, with added improvements including reduced layout thrashing and more efficient incremental updates during streaming.
Also fixes an issue where rapid bursts of tool invocation updates cause brief hangs in the extension host.</p>
</li>
<li>
<p><strong>Chat send performance</strong>: Fixes an issue where chat message sending is blocked by loading chat customizations. The message now visually appears in the chat conversation immediately even if prompts are still loading.</p>
</li>
<li>
<p><strong>Subagent progress</strong>: The expanded view for subagent progress is now more visually distinct, making it easier to follow when a subagent is in progress.</p>
</li>
</ul>
<h2 id="_accessibility" data-needslink="_accessibility">Accessibility</h2>

<ul>
<li>
<p><strong>Accessibility help dialog</strong>: Press <span class="keybinding">Alt+F1</span> (<span class="keybinding">Option+F1</span> on macOS) while the chat input is focused to open the accessibility help dialog. It provides an overview of what the Agents app is, lists available views, and shows keybindings for navigating between them.</p>
</li>
<li>
<p><strong>Keyboard navigation commands</strong>: New keybindings let you quickly focus key views in the Agents app:</p>
<ul>
<li><code>Focus Changes View</code> (<span class="dynamic-keybinding" data-commandid="workbench.action.agentSessions.focusChangesView"></span>)</li>
<li><code>Focus Chat Customizations View</code> (<span class="dynamic-keybinding" data-commandid="aiCustomization.focusView"></span>)</li>
<li><code>Focus Files Explorer View</code> (<span class="dynamic-keybinding" data-commandid="workbench.action.agentSessions.focusChangesFileView"></span>)</li>
</ul>
<p>These keybindings are scoped to the Agents window and do not override their standard VS Code counterparts.</p>
</li>
<li>
<p><strong>Verbosity setting</strong>: The <span class="setting"><span class="setting-dropdown" data-setting-id="accessibility.verbosity.sessionsChat">
    <span class="setting-link-main">
      <span class="codicon codicon-settings-gear dynamic-setting-icon"></span>

<li>

<h2 id="_engineering" data-needslink="_engineering">Engineering</h2>
<h3 id="_github-copilot-is-now-builtin" data-needslink="_github-copilot-is-now-builtin">GitHub Copilot is now built-in</h3>
<p>GitHub Copilot Chat is now a built-in extension in VS Code. New users no longer need to install any extension to start using Copilot features such as chat, inline suggestions, and agents. Copilot is available out of the box as part of the standard VS Code installation.</p>
<p>This change is part of our ongoing effort to make VS Code the open source AI code editor. By shipping Copilot as a built-in extension, we reduce friction for new users and ensure that AI-powered features are seamlessly integrated from the first launch.</p>
<p>Existing users are not affected by this change. If you already have the Copilot extension installed, it continues to work as before.</p>
