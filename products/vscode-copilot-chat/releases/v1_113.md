<hr>
<p>Welcome to the 1.113 release of Visual Studio Code. This release includes various improvements across the <strong>agent and developer experience</strong>.</p>
<ul>
<li>
<p><a href="#_chat-customizations-editor-preview"><strong>Chat customizations</strong></a>: Manage all chat-related customizations from a single, unified interface.</p>
</li>
<li>
<p><a href="#_configurable-thinking-effort-in-model-picker"><strong>Configurable thinking effort</strong></a>: Control a model's reasoning level directly from the UI.</p>
</li>
<li>
<p><a href="#_nested-subagents"><strong>Nested subagents</strong></a>: Allow subagents to invoke other subagents for complex multi-step workflows.</p>

<li>

</li>
<li>

</li>
</ul>
<p>Happy Coding!</p>

<h2 id="_agent-experience" data-needslink="_agent-experience">Agent experience</h2>
<p>Use the same tools and workflows across local, CLI, and Claude agents, and compose multi-step automations with less friction.</p>
<h3 id="_mcp-support-in-copilot-cli-claude-agents" data-needslink="_mcp-support-in-copilot-cli-claude-agents">MCP support in Copilot CLI &amp; Claude agents</h3>
<p>Previously, MCP servers that you configured in VS Code were only available to local agents running in the editor. This release adds support for MCP servers in Copilot CLI &amp; Claude agents.</p>
<p>MCP servers you have registered in VS Code are bridged to Copilot CLI and Claude agents. This applies to both user-defined servers and servers defined in your workspace via <code>mcp.json</code> files.</p>
<p>Learn more about <a href="https://code.visualstudio.com/docs/copilot/customization/mcp-servers">using MCP servers in VS Code</a>.</p>

<h3 id="_agent-debug-logs-for-copilot-cli-and-claude-cli-sessions-preview" data-needslink="_agent-debug-logs-for-copilot-cli-and-claude-cli-sessions-preview">Agent debug logs for Copilot CLI and Claude CLI sessions (Preview)</h3>
<p>The Agent Debug Log panel is the primary tool for understanding what happens when you send a prompt. It shows a chronological event log of agent interactions during a chat session. You can now use the Agent Debug Log panel for Copilot CLI and Claude agent sessions. Support for local agent sessions was already available.</p>
<p><img src="/assets/updates/1_113/agent-flow-chart-v2.png" alt="Screenshot of the Agent Debug Logs panel showing logs from a Copilot CLI session." loading="lazy"></p>
<p>Learn more about the <a href="https://code.visualstudio.com/docs/copilot/chat/chat-debug-view#_agent-debug-log-panel">Agent Debug Log panel</a> in our documentation.</p>
<h3 id="_claude-session-listing-powered-by-sdk-apis" data-needslink="_claude-session-listing-powered-by-sdk-apis">Claude session listing powered by SDK APIs</h3>
<p>VS Code now adopts the official API from the Claude agent SDK to list out sessions and their messages. Previously, we relied on parsing Claude JSONL files on disk, which had a risk of being out of sync if Claude changed their structure. If you experienced issues with the Claude agent not showing all your sessions or messages, this should now be resolved.</p>

<h3 id="_manage-plugin-marketplaces" data-needslink="_manage-plugin-marketplaces">Manage plugin marketplaces</h3>
<p>We added a new command <strong>Chat: Manage Plugin Marketplaces</strong> that lists all configured plugin marketplaces. For each marketplace, you can browse the plugins, open their local directory, and remove them.</p>
<p>Learn more about <a href="https://code.visualstudio.com/docs/copilot/customization/agent-plugins">using agent plugins</a> in the documentation.</p>
<h3 id="_url-handlers-for-plugin-installation" data-needslink="_url-handlers-for-plugin-installation">URL handlers for plugin installation</h3>
<p>You can trigger VS Code plugin installation via URL handlers. To install a marketplace, you can trigger a link with the format:</p>
<pre class="shiki" data-lang="text" shiki-themes="" dark-plus="" light-plus"="" style="--shiki-dark:#D4D4D4;--shiki-light:#000000;--shiki-dark-bg:#1E1E1E;--shiki-light-bg:#FFFFFF" tabindex="0"><code><span class="line"><span>vscode://chat-plugin/add-marketplace?ref=&lt;source&gt;</span></span>
<span class="line"><span></span></span></code></pre>
<p>Where "source" is a Github <code>repo/owner</code> or a base64-encoded Git URI. To install an extension, you can use the following format:</p>
<pre class="shiki" data-lang="text" shiki-themes="" dark-plus="" light-plus"="" style="--shiki-dark:#D4D4D4;--shiki-light:#000000;--shiki-dark-bg:#1E1E1E;--shiki-light-bg:#FFFFFF" tabindex="0"><code><span class="line"><span>vscode://chat-plugin/install?source=&lt;source&gt;</span></span>

<h2 id="_chat-experience" data-needslink="_chat-experience">Chat experience</h2>
<p>Tailor the AI to your project from a single editor, control how much a model reasons before responding, and review visual context without leaving chat.</p>
<h3 id="_chat-customizations-editor-preview" data-needslink="_chat-customizations-editor-preview">Chat Customizations editor (Preview)</h3>
<p>The Chat Customizations editor provides a centralized UI for creating and managing all your chat customizations in one place. The editor organizes customization types into separate tabs, such as custom instructions, prompt files, custom agents, and agent skills. It also provides an embedded code editor with syntax highlighting and validation.</p>
<p><video src="/assets/updates/1_113/chat-customizations-editor.mp4" title="Video showing the Chat Customizations editor with tabs for different customization types." autoplay="" loop="" controls="" muted=""></video></p>
<p>You can create new customizations from scratch or use AI to generate initial content based on your project. To add MCP servers and agent plugins, browse the corresponding marketplace directly from the editor.</p>
<p>To open the editor, select the <strong>Configure Chat (gear icon)</strong> in the Chat view or run <strong>Chat: Open Chat Customizations</strong> from the Command Palette (<span class="dynamic-keybinding" data-commandid="workbench.action.showCommands" data-osx="⇧⌘P" data-win="Ctrl+Shift+P" data-linux="Ctrl+Shift+P"><span class="keybinding">⇧⌘P</span> (Windows, Linux <span class="keybinding">Ctrl+Shift+P</span>)</span>).</p>
<p>Learn more about the <a href="https://code.visualstudio.com/docs/copilot/customization/overview#_chat-customizations-editor">Chat Customizations editor</a> in the documentation.</p>
<h3 id="_configurable-thinking-effort-in-model-picker" data-needslink="_configurable-thinking-effort-in-model-picker">Configurable thinking effort in model picker</h3>
<p>Models that support reasoning, such as Claude Sonnet 4.6 and GPT-5.4, now show a <strong>Thinking Effort</strong> submenu directly in the model picker. You can use this to control how much reasoning the model applies to each request without navigating to VS Code settings. VS Code retains the selected effort level per model across conversations.</p>
<p>Choose a reasoning model in the picker and select the arrow to reveal the available effort levels. The available effort levels might vary by model. Non-reasoning models do not show the submenu.</p>
<p><img src="/assets/updates/1_113/chat-model-picker.png" alt="Screenshot showing the model picker with a Thinking Effort submenu displaying Low, Medium, and High effort levels for a reasoning model." loading="lazy"></p>
<p>The model picker label now also displays the selected effort level, for example "GPT-5.3-Codex · Medium", to make it easier to see which effort level is currently active for each model.</p>
<p>Learn more about <a href="https://code.visualstudio.com/docs/copilot/concepts/language-models#_thinking-and-reasoning">thinking effort and reasoning</a> in the documentation.</p>

<ul>

<h2 id="_editor-experience" data-needslink="_editor-experience">Editor experience</h2>
<p>Develop and test web apps more confidently in the integrated browser, and enjoy a refreshed default look for the editor.</p>
<h3 id="_use-selfsigned-certificates-in-the-integrated-browser" data-needslink="_use-selfsigned-certificates-in-the-integrated-browser">Use self-signed certificates in the integrated browser</h3>
<p>When you are developing web applications that depend on secure HTTPS connections, it's usually necessary to use a self-signed certificate during testing.</p>
<p>Under normal circumstances, such certificates shouldn't be trusted. Previously, any site that presented an untrusted certificate would simply fail to load in the integrated browser, without any option to bypass.</p>
<p>Now, similar to most browsers, you can choose to temporarily trust a certificate that can't be verified, to unblock development in these scenarios.</p>
<p><img src="/assets/updates/1_113/browser-cert-error.png" alt="Screenshot of the integrated browser displaying a certificate error with options to go back or proceed." loading="lazy"></p>
<p>When you proceed, connections to the current host using that certificate are allowed for one week. The URL bar will show that the connection isn't secure, with the option to revoke trust at any time.</p>
<p><img src="/assets/updates/1_113/browser-trust-dialog.png" alt="Screenshot of a popup in the URL bar showing the current page is not secure, with an option to &quot;Revoke and Close&quot;." loading="lazy"></p>
<p>Learn more about the <a href="https://code.visualstudio.com/docs/debugtest/integrated-browser">integrated browser</a> in the documentation.</p>
