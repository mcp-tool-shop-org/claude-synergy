<h2 id="_agents" data-needslink="_agents">Agents</h2>
<h3 id="_orchestrate-tasks-across-projects-with-the-agents-window-preview" data-needslink="_orchestrate-tasks-across-projects-with-the-agents-window-preview">Orchestrate tasks across projects with the Agents window (Preview)</h3>
<p>While VS Code is already used by millions of developers for agentic coding, its editor layout is primarily optimized for single-task, single-workspace workflows. To enable our users (and ourselves!) to work with multiple agents across multiple projects, we created a new type of window:&nbsp;<strong>Agents</strong>.</p>
<p>The new Agents window is a companion to the editor you already know: purpose-built for agent-driven development, with a dedicated space to explore, iterate on, and review tasks across multiple projects, and seamlessly switch between them. And because VS Code is built for developer choice and flexibility, the Agents window lets you pick your agent harness, run agents on remote machines, and configure the environment the way you want it - color themes, keybindings, and extensions included.</p>
<p>The Agents window has been available as part of VS Code Insiders in our past few releases, and with this release, it's now available as a preview in VS Code Stable.</p>
<p><video src="/assets/updates/1_120/agents-demo-20260510.mp4" title="Video showing the Agents window experience in VS Code." controls=""></video></p>
<p>You can open the Agents window in several ways, including the "Open in Agents" button in the VS Code title bar. To learn more about how it works and what you can do with it, visit the <a href="https://aka.ms/VSCode/Agents/docs" class="external-link" target="_blank">Agents window documentation</a>.</p>
<h4 id="_whats-new" data-needslink="_whats-new">What's new?</h4>
<p>If you've already been using the Agents window in Insiders, thank you! We've continued to act on your feedback, with the following improvements landing this week:</p>
<ul>
<li><strong>Preferences persist across new sessions</strong>: Your last choices in dropdowns like agent harness and isolation mode are retained when you create new sessions.</li>
<li><strong>Discard changes more easily</strong>: You can discard edits directly from the Changes panel.</li>
<li><strong>Sync upstream changes in new sessions</strong>: A sync button on the Files panel lets you see upstream changes from the base branch and pull them in before the agent gets to work.</li>
<li><strong>More deterministic changes interactions</strong>: Actions in the Changes panel can complete more quickly as they're now deterministic.</li>
<li><strong>View all changes by default for completed sessions</strong>: When you open a session marked as done, you automatically get a view of the agent's full set of edits at a glance.</li>
<li><strong>Navigate between recent sessions</strong>: Use the arrow buttons in the top-left of the title bar to jump between recent sessions without leaving the window.</li>
<li><strong>Override settings per window</strong>: The Agents window now shares all of your VS Code settings, and you can override specific settings just for the Agents window when you want a different behavior there.</li>
</ul>
<p>Your feedback continues to be a great help in shaping Agents. Please <a href="https://github.com/microsoft/vscode/issues" class="external-link" target="_blank">file issues on GitHub</a> or browse <a href="https://github.com/microsoft/vscode/issues?q=state%3Aopen%20label%3A%22agents-window%22" class="external-link" target="_blank">existing issues</a>.</p>

<h2 id="_language-models" data-needslink="_language-models">Language models</h2>
<p>With Bring Your Own Key (BYOK), you can use your own API keys from providers like Anthropic, OpenAI, and others to take advantage of your own billing or model hosting options. To learn more, see the <a href="https://code.visualstudio.com/docs/copilot/customization/language-models#_bring-your-own-language-model-key">BYOK documentation</a>.</p>
<h3 id="_view-byok-model-token-usage" data-needslink="_view-byok-model-token-usage">View BYOK model token usage</h3>
<p>Managing a model's context window is key to getting good results and controlling costs. The model can lose track of important details from the conversation, and token usage can increase costs. This release brings better visibility into token usage for BYOK models, so you can keep an eye on the context window.</p>
<p>Previously, when chatting with a model you brought via your own API key (Anthropic, OpenAI, or other), the control always displayed 0% and a zero-token count because token accounting was only working for built-in models.</p>
<p>The context window control in the Chat view now shows accurate token usage and percent-full for BYOK models.</p>
<p><img src="/assets/updates/1_120/context-window-byok-token-usage.webp" alt="Screenshot of the context window control in the Chat view showing accurate token usage and percent-full for BYOK models." loading="lazy"></p>
<h3 id="_configure-thinking-effort-for-byok-reasoning-models" data-needslink="_configure-thinking-effort-for-byok-reasoning-models">Configure thinking effort for BYOK reasoning models</h3>
<p>Reasoning-capable language models allow you to configure their "thinking effort", which is a way to trade off between response quality and speed/cost. You can learn more in the <a href="https://code.visualstudio.com/docs/copilot/concepts/language-models#_thinking-effort">thinking effort</a> documentation.</p>
<p>In this release, you can now configure the thinking effort for BYOK reasoning models directly from the model picker in the Chat view. The selected effort is forwarded to the model on every request, letting you trade off latency and cost against answer quality.</p>
<p><img src="/assets/updates/1_120/byok-configure-thinking-effort.webp" alt="Screenshot of the Language Models editor showing the Thinking Effort configuration option for a BYOK model." loading="lazy"></p>
<blockquote><p>Applies to: Bring-Your-Own-Key (BYOK) reasoning models served via OpenAI-compatible endpoints (OpenAI, xAI (Grok), OpenRouter, and custom OpenAI / Azure OpenAI deployments). Anthropic models already supported this; the control is now consistent across providers.</p>
</blockquote><h3 id="_model-picker-organized-by-provider" data-needslink="_model-picker-organized-by-provider">Model picker organized by provider</h3>
<p>The model picker in the Chat view now groups models by their provider, making it easier to find the model you want when you have access to models from multiple sources. You can also search for models by name.</p>
<p><video src="/assets/updates/1_120/model-picker-demo.mp4" title="Video showing the model picker in the Chat view with models grouped by provider and search functionality." autoplay="" loop="" controls="" muted=""></video></p>
<p>Recently used models now display the provider name in grey text alongside the model name, so you can quickly distinguish between similarly named models from different providers.</p>

<h3 id="_terminal-tool-output-compression-preview" data-needslink="_terminal-tool-output-compression-preview">Terminal tool output compression (Preview)</h3>
<p><strong>Setting</strong>: <span class="setting"><span class="setting-dropdown" data-setting-id="chat.tools.compressOutput.enabled">
    <span class="setting-link-main">
      <span class="codicon codicon-settings-gear dynamic-setting-icon"></span>

<p>Long terminal output from commands like <code>git diff</code>, <code>ls -l</code>, and <code>npm install</code> can consume a large share of the model's context window, which leaves less room for your code and the agent's reasoning.</p>
<p>When you enable the <span class="setting"><span class="setting-dropdown" data-setting-id="chat.tools.compressOutput.enabled">
    <span class="setting-link-main">
      <span class="codicon codicon-settings-gear dynamic-setting-icon"></span>
      chat.tools.compressOutput.enabled
    </span>
    <button type="button" class="setting-dropdown-trigger" aria-haspopup="menu" aria-expanded="false" aria-label="Open setting in VS Code">
        <svg class="setting-dropdown-chevron" viewBox="0 0 16 16" fill="currentColor" aria-hidden="true">
        <path d="M7.976 10.072l4.357-4.357.62.618L8.284 11h-.618L3 6.333l.619-.618 4.357 4.357z"></path>
        </svg>
    </button>
    <span class="setting-dropdown-menu" role="menu" aria-label="Open setting">
      <span role="menuitem" class="setting-action-item" data-version="stable" tabindex="0">Open in VS Code</span>
      <span role="menuitem" class="setting-action-item" data-version="insiders" tabindex="-1">Open in VS Code Insiders</span>
    </span>
  </span></span> setting, VS Code post-processes the output of these commands before sending it to the model. Large unchanged hunks in diffs are collapsed, lockfile and snapshot diffs are dropped, <code>ls -l</code> is reduced to entry names, and <code>npm install</code> progress bars, deprecation warnings, and audit summaries are stripped.</p>
<p>A short banner is prepended to any compressed output, so the model can see which filters fired and how to disable compression if it needs the raw text.</p>
<h3 id="_risk-assessment-for-terminal-commands-experimental" data-needslink="_risk-assessment-for-terminal-commands-experimental">Risk assessment for terminal commands (Experimental)</h3>
<p><strong>Setting</strong>: <span class="setting"><span class="setting-dropdown" data-setting-id="chat.tools.riskAssessment.enabled">
    <span class="setting-link-main">
      <span class="codicon codicon-settings-gear dynamic-setting-icon"></span>

    </span>
    <button type="button" class="setting-dropdown-trigger" aria-haspopup="menu" aria-expanded="false" aria-label="Open setting in VS Code">

    <span class="setting-dropdown-menu" role="menu" aria-label="Open setting">
      <span role="menuitem" class="setting-action-item" data-version="stable" tabindex="0">Open in VS Code</span>
      <span role="menuitem" class="setting-action-item" data-version="insiders" tabindex="-1">Open in VS Code Insiders</span>
    </span>
  </span></span></p>
<p>To help you decide quickly whether a command is worth a closer look, terminal command confirmations now include a risk badge with an AI-generated explanation of what the command does.</p>
<p>Each badge shows one of three levels along with a one-sentence summary tailored to the specific command:</p>
<ul>
<li><strong>Safe</strong> (green): reads files or prints output without making changes.</li>
<li><strong>Caution</strong> (orange): modifies the workspace, installs packages, or sends data over the network.</li>
<li><strong>Review carefully</strong> (red): performs an action that may be difficult or impossible to undo, such as force-pushing to a remote or deleting files outside the workspace.</li>
</ul>

<h2 id="_proposed-apis" data-needslink="_proposed-apis">Proposed APIs</h2>
<h3 id="_custom-editor-diffs" data-needslink="_custom-editor-diffs">Custom editor diffs</h3>
<p>The new <code>customEditorDiffs</code> proposed API lets custom editors render diffs with a dedicated diff UI. This is what powers the new <a href="#_markdown-preview-for-diffs-preview">Markdown preview in the diff view</a>, and it opens up a much nicer compare experience where a textual diff of the underlying source isn't useful.</p>
<p>A custom editor provider can opt in by implementing one or both of the following on <code>CustomReadonlyEditorProvider</code> or <code>CustomTextEditorProvider</code>:</p>
<ul>
<li>
<p><code>resolveCustomEditorInlineDiff(documents, webviewPanel, token)</code>: render the diff in a single webview, with both the original and modified documents available to the extension.</p>
</li>
<li>
<p><code>resolveCustomEditorSideBySideDiff(documents, webviewPanels, token)</code>: render the diff using two webviews, one for each side, with VS Code coordinating layout and scroll sync.</p>
</li>
</ul>
<p>Combined with <a href="#_separate-custom-editor-priorities-diffs-and-merges"><code>diffEditorPriority</code></a>, extensions now have full control over whether their custom editor handles diffs and how those diffs are presented. See <a href="https://github.com/microsoft/vscode/issues/138525" class="external-link" target="_blank">issue #138525</a> to follow along and provide feedback.</p>
