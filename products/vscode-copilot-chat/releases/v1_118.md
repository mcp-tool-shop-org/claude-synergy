<h2 id="_agent-experience" data-needslink="_agent-experience">Agent experience</h2>
<h3 id="_visual-studio-code-agents-insiders" data-needslink="_visual-studio-code-agents-insiders">Visual Studio Code Agents (Insiders)</h3>
<blockquote><p><strong>Note</strong>: The Visual Studio Code Agents app is currently in preview and only available when installing VS Code Insiders.</p>
</blockquote><p>The <a href="https://aka.ms/VSCode/Agents/docs" class="external-link" target="_blank">Visual Studio Code Agents</a> app is a companion app that ships alongside VS Code Insiders. It provides a focused, agent-native environment where you can run parallel sessions across repos and iterate on multi-step coding tasks. We first introduced the Agents app in <a href="https://code.visualstudio.com/updates/v1_115#_visual-studio-code-agents-preview">1.115</a> and continue to refine it based on user feedback.</p>
<p>In this release, you can discover the Agents app directly from the VS Code Insiders title bar, making it easy to jump into an agent-powered workflow. We also published dedicated <a href="https://aka.ms/VSCode/Agents/docs" class="external-link" target="_blank">Agents documentation</a> to help you get started.</p>
<p>Recent feature highlights include:</p>
<ul>
<li>
<p><strong>Shared state across VS Code and Agents</strong>: The Agents app shares more state with VS Code Insiders for a smoother transition between the two. This includes authentication (on Windows), AI customizations, workspace trust, recent folders, and keyboard shortcuts.</p>
</li>
<li>
<p><strong>Claude agent</strong>: The Claude Agent is available in the Agents app, so that you can use it alongside other agents like Copilot CLI or Copilot Cloud for your coding tasks.</p>
</li>
<li>
<p><strong>Web client</strong>: Access the Agents experience from the browser at <a href="https://insiders.vscode.dev/agents" class="external-link" target="_blank">insiders.vscode.dev/agents</a>, bringing the agent-native workflow to any machine where you have a Dev Tunnel running (via <code>code-insiders tunnel</code>). To get started, <a href="https://code.visualstudio.com/insiders">download VS Code Insiders</a> and run <code>code-insiders tunnel</code> to set up a <a href="https://code.visualstudio.com/docs/remote/tunnels">Dev Tunnel</a>. You can then connect to it from the web.</p>
</li>
<li>
<p><strong>Background browsers</strong>: The integrated browser persists across sessions, so it no longer refreshes when you return to a session. This makes context switching smoother when using the integrated browser to preview changes while the agent works.</p>
</li>
<li>
<p><strong>Layout controls for changes</strong>: When the agent makes changes, you can open the diff view side-by-side with the Chat view or open it in a modal window to focus on the changes. Use the layout controls in the diff view toolbar to toggle between different display modes.</p>
</li>
<li>
<p><strong>Dynamic title bar entry points</strong>: Switch between VS Code Insiders and the Agents app with a single click. Select <strong>Open in Agents</strong> from the VS Code Insiders title bar to jump into the Agents app, or select <strong>Open in VS Code</strong> from the Agents title bar to return to the Insiders editor.</p>
</li>
</ul>
<p>Your feedback helps us shape the Agents experience - please continue sharing it with us by <a href="https://github.com/microsoft/vscode/issues" class="external-link" target="_blank">filing issues on GitHub</a>. You can also explore <a href="https://github.com/microsoft/vscode/issues?q=state%3Aopen%20label%3A%22agents-app%22" class="external-link" target="_blank">existing issues</a> to see what others have reported and provide your feedback on specific topics.</p>

<h3 id="_synced-session-titles-for-copilot-cli" data-needslink="_synced-session-titles-for-copilot-cli">Synced session titles for Copilot CLI</h3>
<p>The chat session title is used across different chat surfaces like the chat sessions list, the chat editor tab and header, and the Copilot CLI terminal interface to provide a consistent identifier for the session. Depending on where you renamed a <a href="https://code.visualstudio.com/docs/copilot/agents/copilot-cli">Copilot CLI</a> session, other chat surfaces could still show the old title.</p>
<p>VS Code adopts the Copilot SDK session title APIs as the source of truth and routes the sessions list and chat editor header through a single title resolver to keep the displayed title consistent across surfaces. The chat sessions list, the chat editor tab and header, and <code>copilot --resume</code> in the terminal now all stay in sync when you rename a session, regardless of where the rename originated.</p>
<p>Renames performed in the terminal from Copilot CLI are also picked up by VS Code the next time the session metadata is read.</p>

<h2 id="_codebase-search-and-context" data-needslink="_codebase-search-and-context">Codebase search and context</h2>
<h3 id="_semantic-indexing-of-nongithub-repositories-rolled-out-to-all-users" data-needslink="_semantic-indexing-of-nongithub-repositories-rolled-out-to-all-users">Semantic indexing of non-GitHub repositories rolled out to all users</h3>
<p>When you ask Copilot a question like "where do we handle user authentication?", the agent has to translate your fuzzy intent into the exact files and symbols that matter. Plain text search only matches the literal words you typed, so it often misses the relevant code when your codebase uses different terminology. Semantic indexing lets agents search by <em>meaning</em>, surfacing files that use related terms like <code>login</code>, <code>signIn</code>, <code>verifyCredentials</code>, or <code>OAuth token exchange</code>, even if the word "authentication" never appears in the code. This gives the agent better grounding for answers and edits.</p>
<p>Semantic indexing is now available in all workspaces. Previously, this capability was limited to workspaces that use GitHub or ADO repositories.</p>
<p>The semantic index is built and maintained automatically. Workspaces that use a GitHub or ADO repository can typically use semantic search instantly, while other workspaces might require a few minutes to build up the initial index. You can also use the <strong>Build Codebase semantic index</strong> command to explicitly build the index for the current workspace.</p>
<p>Semantic search is one of the many tools Copilot uses to understand your workspace when answering questions and generating edits. Copilot will pick the best tools for the job, so you generally do not have to micromanage how it searches. Check out the <a href="https://code.visualstudio.com/docs/copilot/reference/workspace-context">How Copilot understands your workspace</a> docs for more details on semantic search and the other tools that Copilot uses.</p>
<h3 id="_github-text-search-across-repos-or-orgs" data-needslink="_github-text-search-across-repos-or-orgs">GitHub text search across repos or orgs</h3>
<p>When the agent needs to look up an exact string, API name, or error message in code outside your current workspace, semantic search isn't always the right fit. You want a precise match across a known repository or your entire organization, not a fuzzy one.</p>
<p>To support this, Copilot now includes a built-in <code>githubTextSearch</code> agent tool that does a grep-style search through the code of a GitHub repository or an entire GitHub organization. This complements the existing <code>githubRepo</code> tool, which does semantic searches within a GitHub repo. Together, these tools give the agent a richer way to learn from codebases outside the one you are currently working on.</p>
<p>For more advanced GitHub features such as searching and managing issues or pull requests, consider using the <a href="https://github.com/github/github-mcp-server" class="external-link" target="_blank">GitHub MCP server</a>.</p>

<h3 id="_workspace-mcpjson-files-and-server-deduplication" data-needslink="_workspace-mcpjson-files-and-server-deduplication">Workspace <code>.mcp.json</code> files and server deduplication</h3>
<p>We've added support for workspace-level <code>.mcp.json</code> files to declare MCP servers, aligning with other tools such as the Copilot CLI.</p>
<p>Additionally, we've introduced behavior to deduplicate MCP servers that share the same name. By default, only the most-specific MCP server will be enabled, and enabling a server will disable other servers by the same name. You can control which MCP servers are enabled by searching <code>@mcp @installed</code> in the extensions view, or via the <strong>Chat: Open Customizations</strong> window.</p>
<h2 id="_improving-token-efficiency" data-needslink="_improving-token-efficiency">Improving token efficiency</h2>

<h3 id="_prompt-caching-efficiency" data-needslink="_prompt-caching-efficiency">Prompt caching efficiency</h3>
<p>Over the past several iterations, we have improved cache reuse across system prompts, tools, conversation history, and summarization, without changing how the agent behaves. <p><strong>Strategic cache breakpoint placement.</strong> We audited where cache breakpoints are set so they are used efficiently and placed at stable boundaries: end of system prompt, end of tools, end of the most recent tool turn, and conversation turn boundaries. As a result, once an agent session is underway, more than 93% of each request is reused from cache instead of being charged as new input.</p>

<h3 id="_tool-search-tool" data-needslink="_tool-search-tool">Tool search tool</h3>
<p>The tool search tool keeps requests lean by splitting the agent's toolset into two groups. <h3 id="_new-tools-for-search-and-execution" data-needslink="_new-tools-for-search-and-execution">New tools for search and execution</h3>
<p>This release brings two new specialized agentic tools: Search and Execution. Both are powered by small, purpose-built models that cost significantly less to run. After over a month of flighting, we are seeing promising results, with token savings of up to 20%.</p>
<h4 id="_agentic-search-tool" data-needslink="_agentic-search-tool">Agentic search tool</h4>
<p>The agentic search tool handles codebase exploration and context retrieval. When the main agent needs context, it describes what it's looking for in plain language, and the search tool takes over. The search tool then runs an independent process to search your workspace using grep, file search, semantic search, and file reading, then returns the most relevant results.</p>
<p>Under the hood, this tool is powered by a fine-tuned small language model, trained to run many searches in parallel across a minimal number of turns. This tight scope keeps latency and cost low without sacrificing retrieval quality.</p>
<p>Rollout continues over the coming month, bringing these savings to all Copilot Chat users.</p>
<h4 id="_agentic-execution-tool" data-needslink="_agentic-execution-tool">Agentic execution tool</h4>
<p>The agentic execution tool handles anything related to running terminal commands. When the agent has to run tests or check a build, it hands the task off to the execution tool, which runs the commands and reports back. To keep the scope tight, the execution tool can only run terminal commands, and it is capped at 10 terminal calls per invocation so it cannot loop indefinitely.</p>
<p>Terminal output tends to be long and noisy. Once the task is done, the execution tool filters that output down to what a coding agent actually needs and passes only the relevant parts back. Offloading this work from the main model to a smaller, faster one keeps verbose output from eating into your token usage.</p>

<h3 id="_websockets-supported-for-openai-models" data-needslink="_websockets-supported-for-openai-models">WebSockets supported for OpenAI models</h3>
<p>For OpenAI models that support it, chat requests now use <a href="https://developers.openai.com/api/docs/guides/websocket-mode" class="external-link" target="_blank">WebSocket mode</a> on the Responses API. Instead of opening a new HTTP request per turn, VS Code keeps a persistent WebSocket connection and sends only new input items along with the previous response ID. <h2 id="_editor-experience" data-needslink="_editor-experience">Editor Experience</h2>
<h3 id="_optimized-loading-of-large-local-resources-in-webviews" data-needslink="_optimized-loading-of-large-local-resources-in-webviews">Optimized loading of large local resources in webviews</h3>
<p>We've optimized how <a href="https://code.visualstudio.com/api/extension-guides/webview">webviews</a> load local resources to improve speed and reduce memory usage. This change benefits any extension that uses webviews or custom editors, as well as built-in VS Code features such as notebook rendering.</p>
<p>Webviews in VS Code use a service worker to load resources from the workspace or host file system. The service worker intercepts the request for the local file and then proxies it through VS Code's file system calls. This enables us to not only load resources from the disk but also from virtual file systems contributed by extensions.</p>
<p>Previously, for file system requests, VS Code would read the entire file into a buffer and then send it to the webview's service worker. This works for a few small JavaScript and image files, but not when you're loading 20 video files that are tens to hundreds of MB each.</p>
<p>Now, we stream the file contents to the service worker in chunks. This approach improves responsiveness and also reduces the amount of data that VS Code has to accumulate before handing it off to the browser engine.</p>
<p>We further optimized the streaming by adopting <a href="https://github.com/whatwg/streams/blob/main/explainers/transferable-streams.md#transferable-streams-explained" class="external-link" target="_blank">transferable streams</a>. A file stream is created in the main VS Code renderer process and consumed directly by <code>new Response(...)</code> inside the webview's service worker. This bypasses what were previously multiple layers of <code>postMessage</code> calls.</p>
