# mcp-inspector 1.0.7

## What's Changed

### v1.x security fixes

1.0.7 is a security release for the deprecated v1 line. Upgrade with `npx @modelcontextprotocol/inspector@v1-latest`, or move to v2 (`@latest`).

* **The proxy no longer lets a NAT64 or other IPv4-embedding IPv6 address reach cloud metadata.** The SSRF guard used to match IPv6 addresses by how they were written. It now parses each address into its eight 16-bit groups and matches on value, so every spelling of a blocked address is caught. It also treats `::ffff:0:0/96`, `64:ff9b::/96` and `64:ff9b:1::/48` as IPv4-embedding, and re-checks the IPv4 address in the low 32 bits. On a host with NAT64/DNS64 egress, a malicious MCP server could previously use `http://[64:ff9b::a9fe:a9fe]/` to reach `169.254.169.254`. NAT64 addresses that embed a public IPv4 address are still allowed. ([GHSA-v2gx-m79c-pvxj](https://github.com/modelcontextprotocol/inspector/security/advisories/GHSA-v2gx-m79c-pvxj)) by @cliffhall in https://github.com/modelcontextprotocol/inspector/pull/3051
* **`npx -y @modelcontextprotocol/inspector-server` starts again.** The server imported `node-fetch` without declaring it, so installing it on its own crashed with `ERR_MODULE_NOT_FOUND` in every release since 0.21.0. It now declares `node-fetch`, and the client declares `open` and `spawn-rx`. by @cliffhall in https://github.com/modelcontextprotocol/inspector/pull/3056
* **`npx -y @modelcontextprotocol/inspector-client` starts.** Its launcher reached the proxy and its own UI server through paths that exist only inside `@modelcontextprotocol/inspector`. It now runs its own UI server, and falls back to a declared `@modelcontextprotocol/inspector-server` dependency when there is no sibling server. `@modelcontextprotocol/inspector` itself is unchanged. by @cliffhall in https://github.com/modelcontextprotocol/inspector/pull/3060
