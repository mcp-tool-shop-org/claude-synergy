# mcp-inspector 2.17.0

## What's Changed

### Security fixes

2.17.0 fixes one vulnerability reported privately against v2. Upgrade with `npx @modelcontextprotocol/inspector@latest`. It also affects the deprecated v1 line, where it is fixed in 1.0.7 (`@v1-latest`).

* **The SSRF guard now refuses NAT64 and other IPv4-embedding IPv6 addresses that point at cloud metadata.** It used to match IPv6 addresses by how they were written. It now parses each one and matches on its value, and re-checks the IPv4 address carried in `::ffff:0:0/96`, `64:ff9b::/96` and `64:ff9b:1::/48`. On a host with NAT64/DNS64 egress, a malicious MCP server could previously name an authorization server such as `http://[64:ff9b::a9fe:a9fe]` to reach `169.254.169.254` through the web backend or the CLIs. NAT64 addresses that embed a public IPv4 address are still allowed. ([GHSA-v2gx-m79c-pvxj](https://github.com/modelcontextprotocol/inspector/security/advisories/GHSA-v2gx-m79c-pvxj))
