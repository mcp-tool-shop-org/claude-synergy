# mcp-inspector 2.12.0

## What's Changed

### Security fixes

2.12.0 fixes three vulnerabilities that affect every v2 release from 2.0.0 through 2.11.0. Upgrade with `npx @modelcontextprotocol/inspector@latest`.

* **Opening a URL is restricted to `http(s)`, and the Inspector opens the URL it checked rather than the raw input.** A remote server's OAuth authorization URL can no longer run commands through the opener on Windows and WSL. `open` is bumped to v11 ([GHSA-q978-78c7-phqw](https://github.com/modelcontextprotocol/inspector/security/advisories/GHSA-q978-78c7-phqw))
* **The production web server validates the `Host` header** and answers any host outside its allow-list with 403 before serving a page. That closes the DNS-rebinding route to the API token and stored OAuth tokens. A new `MCP_INSPECTOR_ALLOWED_HOSTS` covers reverse proxies that rewrite `Host` ([GHSA-vcc9-3xgm-p9v4](https://github.com/modelcontextprotocol/inspector/security/advisories/GHSA-vcc9-3xgm-p9v4))
* **The `/api/fetch` proxy caps upstream response bodies at 4 MiB**, refusing early when `Content-Length` declares more, and still relays the status of an oversized error response ([GHSA-m5pj-3536-3xcp](https://github.com/modelcontextprotocol/inspector/security/advisories/GHSA-m5pj-3536-3xcp))

### New configuration

* `MCP_INSPECTOR_ALLOWED_HOSTS`: unset by default. Comma-separated extra hostnames the prod web server accepts in `Host`. A leading `.` admits a domain and its subdomains. See the web README's "The Host allow-list" section.
* `INSPECTOR_TLS_KEY_PATH` and `INSPECTOR_TLS_CERT_PATH`: unset by default. Set both to serve the web UI over https, in both prod and dev. See [`docs/tls.md`](https://github.com/modelcontextprotocol/inspector/blob/main/docs/tls.md).
