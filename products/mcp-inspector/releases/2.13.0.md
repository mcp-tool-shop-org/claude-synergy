# mcp-inspector 2.13.0

## Security: Node.js runtime advisories (October 2026)

On October 20, 2026, eMudhra disclosed that the private keys for eight of its intermediate CA certificates could be recovered from the public certificates. On October 21, Node.js shipped [security releases](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases) that update its bundled CA certificates for the compromise. The same releases fix several unrelated high-severity runtime CVEs, including DNS name truncation, TLS hostname checks on non-canonical IP addresses, and an out-of-bounds write in the Brotli decoder.

**How this release stands**

- **The Inspector relies on the Node.js runtime for certificate checks.** It ships no CA certificates of its own and doesn't opt into the system trust store. Every HTTPS connection it makes, to MCP servers and to OAuth discovery and token endpoints, is verified by the Node.js it runs on.
- **The Docker image needs no action.** `ghcr.io/modelcontextprotocol/inspector:2.13.0` runs Node.js **22.23.4**, a patched release, and contains no system CA store.
- **This release also updates two of its own dependencies past published advisories:** `undici` (#2812) and `fast-uri` (#2820).

**If you run the Inspector from npm (`npx` or a global install)**

It runs on your Node.js, which we can't update for you. Please run Node.js **22.23.4, 24.22.1 or 26.12.1, or later**, and check with `node --version`. The package's `engines` field still accepts Node.js 22.19.0 and up, so npm won't warn you about an older, unpatched runtime. Node.js 20 and earlier are end-of-life, get no fix, and aren't supported by Inspector v2.
