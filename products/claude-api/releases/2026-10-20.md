# claude-api — October 20, 2026

<ul>
<li><a href="/docs/en/manage-claude/inference-hooks">Inference hooks</a> are out of beta for Claude Enterprise organizations.</li>
<li>We’ve launched <a href="/docs/en/manage-claude/user-profiles">user profiles</a>, so you can tell Anthropic which of your end customers each API request is for. If you operate a platform or gateway, or resell API access, a safety enforcement action can then apply to one end customer instead of your whole organization. The SDK and the <code>ant</code> CLI support the new <a href="/docs/en/api/user_profiles"><code data-link-continues="after">/v1/user_profiles</code> endpoints</a>.</li>
<li>We’ve added <a href="/docs/en/manage-claude/organization-webhooks">organization webhooks</a> to the <a href="/docs/en/manage-claude/admin-api">Admin API</a>, in beta with the <code>webhooks-2026-10-07</code> beta header. Its <a href="/docs/en/api/beta/organization/webhooks"><code data-link-continues="after">/v1/organizations/webhooks</code> endpoints</a> register webhook endpoints for two event types: one for when Anthropic restricts or bans one of your organization’s user profiles, and one for when the restriction or ban ends. To request access, contact your Anthropic account team.</li>
<li>Organization admins can now turn off web fetch for their organization on the <a href="/settings/capabilities"><strong>Capabilities</strong></a> page of the Claude Console. With web fetch off, a Messages API request that includes the web fetch tool fails with a 400 error. In a Claude Managed Agents session, <code>web_fetch</code> calls return an error result to the agent instead. With web fetch on, admins can also set allowed or blocked domains for web fetch on the same page. See <a href="/docs/en/agents-and-tools/tool-use/web-fetch-tool#how-to-use-web-fetch">How to use web fetch</a> and <a href="/docs/en/agents-and-tools/tool-use/server-tools#domain-filtering">Domain filtering</a>.</li>
<li>In Claude Managed Agents, the <a href="/docs/en/managed-agents/tools#available-tools"><code data-link-continues="after">web_fetch</code> tool</a> now follows your organization’s web fetch domain restrictions set on the <a href="/settings/capabilities"><strong>Capabilities</strong></a> page of the Claude Console. A URL, including one reached by a redirect, must pass both the organization’s list and the <code>allowed_domains</code> or <code>blocked_domains</code> list on the agent’s <code>web_fetch</code> tool. See <a href="/docs/en/managed-agents/tools-web-restrictions">Restrict web search and web fetch domains</a>.</li>
<li>In Claude Managed Agents, sessions follow your organization’s web search settings on the <a href="/settings/capabilities"><strong>Capabilities</strong></a> page of the Claude Console: the <strong>Allow web search</strong> setting since October 6, and its web search domain restrictions since October 14. The agent receives only the search results that both the organization’s domain restrictions and the <code>allowed_domains</code> or <code>blocked_domains</code> list on the agent’s <a href="/docs/en/managed-agents/tools#available-tools"><code data-link-continues="after">web_search</code> tool</a> allow. See <a href="/docs/en/managed-agents/tools-web-restrictions">Restrict web search and web fetch domains</a>.</li>
</ul>
