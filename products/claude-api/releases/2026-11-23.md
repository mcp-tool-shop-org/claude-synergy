# claude-api — November 23, 2026

<ul class="docs-public-part">
<li id="analytics-api-web-search-counts">A fix is live for an undercount of web searches in the <a id="_R_122g26aqav5ut5u7ivd5urdalb_" aria-describedby="_R_322g26aqav5ut5u7ivd5urdalbH2_" href="/docs/en/api/beta/organization/analytics/users/list">List User Activity</a><span id="_R_322g26aqav5ut5u7ivd5urdalbH2_" data-find-omitted="" class="sr-only select-none">Preview with links to the API reference available — press Tab until focus enters the card, Escape to return.</span> endpoint of the <a href="/docs/en/manage-claude/analytics-api">Claude Enterprise Analytics API</a>. The top-level <code>web_search_count</code> did not count every search tool that Claude uses in chats, so it left out some searches. It now includes them, so it can be higher. Most of the added searches come from <a href="/docs/en/manage-claude/analytics-api#how-metrics-are-defined">Chat and Cowork unified</a>.</li>
<li>The web search fix applies to data for November 17, 2026 (UTC), and later, so counts that you already pulled for those days can change. It does not recount earlier days.</li>
<li id="analytics-api-connector-sign-in-counts">A fix is live for an undercount in the <a id="_R_126g26aqav5ut5u7ivd5urdalb_" aria-describedby="_R_326g26aqav5ut5u7ivd5urdalbH2_" href="/docs/en/api/beta/organization/analytics/connectors/list">Get Connector Usage</a><span id="_R_326g26aqav5ut5u7ivd5urdalbH2_" data-find-omitted="" class="sr-only select-none">Preview with links to the API reference available — press Tab until focus enters the card, Escape to return.</span> endpoint of the <a href="/docs/en/manage-claude/analytics-api">Claude Enterprise Analytics API</a>. In chats that the <a href="/docs/en/release-notes/overview#analytics-api-chat-session-counting">session counting change</a> reached, <code>individual_auth_distinct_user_count</code> and <code>managed_auth_distinct_user_count</code> left out users who used a connector. For most organizations, these counts now include most of those users. They can be higher, and can show a number where they used to be <code>null</code>.</li>
<li>The connector fix applies to data for November 19, 2026 (UTC), and later, so counts that you already pulled for those days can change. It does not recount earlier days.</li>
<li id="analytics-api-project-message-counts">On November 24, 2026, a fix for an undercount of project activity in the <a href="/docs/en/manage-claude/analytics-api">Claude Enterprise Analytics API</a> will go live. The <a id="_R_14ag26aqav5ut5u7ivd5urdalb_" aria-describedby="_R_34ag26aqav5ut5u7ivd5urdalbH2_" href="/docs/en/api/beta/organization/analytics/apps/chat/projects/list">Get Chat Project Usage</a><span id="_R_34ag26aqav5ut5u7ivd5urdalbH2_" data-find-omitted="" class="sr-only select-none">Preview with links to the API reference available — press Tab until focus enters the card, Escape to return.</span> endpoint leaves out some messages in project chats. One example is messages sent after a chat moves into a Cowork cloud session. After the fix, it will count most of those messages. <code>message_count</code>, <code>distinct_conversation_count</code>, and <code>distinct_user_count</code> can then be higher, and more projects can appear in the results.</li>
<li>The <a id="_R_12cg26aqav5ut5u7ivd5urdalb_" aria-describedby="_R_32cg26aqav5ut5u7ivd5urdalbH2_" href="/docs/en/api/beta/organization/analytics/users/list">List User Activity</a><span id="_R_32cg26aqav5ut5u7ivd5urdalbH2_" data-find-omitted="" class="sr-only select-none">Preview with links to the API reference available — press Tab until focus enters the card, Escape to return.</span> endpoint will change in the same way when you filter by <code>project_id</code>. <code>message_count</code> and <code>distinct_conversation_count</code> can be higher, <code>last_activity_date</code> can be later, and more users can appear. Without the filter, some of these messages count in <code>chat_cowork_unified_metrics.sessions.message_count</code>. So the chat <code>message_count</code> for a user can be higher with the filter than without it.</li>
<li>The project fix will apply to data for November 20, 2026 (UTC), and later, so counts that you already pulled for those days can change. It does not recount earlier days.</li>
<li id="claude-opus-4-5-deprecation">We announced the deprecation of the Claude Opus 4.5 model (<code>claude-opus-4-5-20251101</code> and <code>claude-opus-4-5</code>), with retirement on the Claude API scheduled for January 22, 2027. We recommend migrating to Claude Opus 5.5. See <a href="/docs/en/models/opus-5-5/migration-guide#migrating-from-claude-opus-45">Migrating from Claude Opus 4.5 or earlier</a>. To check which dates apply on other platforms, see <a href="/docs/en/about-claude/model-deprecations">Model deprecations</a>.</li>
<li id="enterprise-frontier-safeguards">We’ve launched <a href="/docs/en/manage-claude/enterprise-frontier-safeguards/overview">Enterprise Frontier Safeguards</a> (EFS) in beta on Claude Platform<!-- -->,<!-- --> Claude Platform on AWS<!-- -->, and Claude Models on Google Cloud (Anthropic managed)<!-- -->. EFS is Zero Data Retention (ZDR) for eligible organizations that use <a href="/docs/en/manage-claude/api-and-data-retention#model-specific-data-retention-requirements">Claude’s most capable models</a>. Anthropic doesn’t retain your prompts and responses. Encrypted copies of them, called Sealed Safety Data, go to a bucket in your own cloud account. A workspace on Anthropic-managed storage isn’t on EFS, because Anthropic stores that workspace’s Sealed Safety Data. To get access, see <a href="/docs/en/manage-claude/enterprise-frontier-safeguards/setup-console">Setup guide</a>.</li>
<li id="storage-webhook-events">We’ve added two event types to <a href="/docs/en/manage-claude/organization-webhooks#customer-owned-storage-events">organization webhooks</a>, which are in beta. We send <code>external_storage.failed</code> when a bucket that you use as <a href="/docs/en/manage-claude/enterprise-frontier-safeguards/customer-owned-storage">customer-owned storage</a> fails our daily check, and <code>external_storage.recovered</code> when it passes again.</li>
</ul>
