# claude-api — August 19, 2026

<ul>
<li>The <a href="/docs/en/agents-and-tools/tool-use/computer-use-tool">computer use tool</a> is out of beta on the Claude API as the <code>computer_toolset_20260801</code> toolset: no beta header, batch actions (several actions in one turn), <code>zoom</code> enabled by default, and per-member configuration through <code>configs</code>. Earlier beta versions remain available. Upgrading an existing integration changes the request shape and tool handling; see <a href="/docs/en/agents-and-tools/tool-use/computer-use-tool#migrate-from-computer-20251124">Migrate from <code data-link-continues="before">computer_20251124</code></a>.</li>
<li>We’ve launched the <a href="/docs/en/agents-and-tools/tool-use/browser-use-tool">browser use tool</a> (<code>browser_toolset_20260801</code>), a client toolset for driving a browser that your application hosts. It works inside a browser viewport rather than a whole desktop, reading the page itself (its accessibility tree, elements, forms, and tabs) and adding element references, form input, tab management, download reporting, and opt-in file upload on top of screenshot-and-click control.</li>
<li>Both toolsets are available for Claude Fable 5, Claude Mythos 5, Claude Opus 5, Claude Sonnet 5, and Claude Opus 4.8 on the Claude API.</li>
<li>The <a href="/docs/en/build-with-claude/files">Files API</a> is out of beta on the Claude API. Requests to the <code>/v1/files</code> endpoints, and Messages API requests that reference an uploaded file, no longer require the <code>files-api-2025-04-14</code> beta header. Requests sent without the header use the current response format: <a href="/docs/en/build-with-claude/files#file-expiration">file expiration</a> (set <code>expires_in_seconds</code> when you upload a file; file objects report <code>expires_at</code>), and <code>page</code> and <code>next_page</code> <a href="/docs/en/api/overview#pagination">pagination</a> plus an <code>ids[]</code> filter when you <a href="/docs/en/build-with-claude/files#list-files">list files</a>. <code>/v1/files</code> requests that still send the beta header keep working and return the previous response format.
To move an existing integration off the header, see <a href="/docs/en/build-with-claude/files#migrate-from-files-api-2025-04-14">Migrate from <code data-link-continues="before">files-api-2025-04-14</code></a>.</li>
<li><a href="/docs/en/agents-and-tools/agent-skills/overview">Agent Skills</a> and the Skills API (<code>/v1/skills</code>) are out of beta on the Claude API. Requests no longer require the <code>skills-2025-10-02</code> beta header, including Messages API requests that load Skills through the <code>container</code> parameter. Requests that still send the header continue to work unchanged. See <a href="/docs/en/build-with-claude/skills-guide">Using Agent Skills with the API</a>.
To move an existing integration off the header, see <a href="/docs/en/build-with-claude/skills-guide#migrate-from-skills-2025-10-02">Migrate from <code data-link-continues="before">skills-2025-10-02</code></a>.</li>
<li>The <a href="/docs/en/api/beta/organization">Admin API user-management endpoints</a> for <strong>Claude Enterprise</strong> (claude.ai) organizations (members, invites, groups, and custom roles) are out of beta. The <code>anthropic-beta: ce-user-management-2026-07-13</code> header is no longer required on group and custom-role requests; requests that still send it are accepted unchanged. See <a href="/docs/en/manage-claude/user-management">User management</a>.</li>
<li>You can now restrict which sites a Claude Managed Agents agent’s <code>web_search</code> and <code>web_fetch</code> tools can reach. Set <code>allowed_domains</code> or <code>blocked_domains</code> on the tool’s entry in the <code>agent_toolset_20260401</code> <code>configs</code> array; <code>web_fetch</code> also accepts <code>max_content_tokens</code> and <code>web_search</code> accepts <code>user_location</code>. Each <code>configs</code> entry is identified by its <code>name</code> and typed by an optional <code>type</code>, and requests that pass only <code>name</code>, <code>enabled</code>, and <code>permission_policy</code> continue to work; in the typed SDKs, <code>configs</code> entries become <a href="/docs/en/managed-agents/tools#config-entry-types-in-the-sdks">per-tool types</a>. See <a href="/docs/en/managed-agents/tools-web-restrictions">Restrict web search and web fetch domains</a>.</li>
<li>Claude Managed Agents sessions that run in a <a href="/docs/en/managed-agents/self-hosted-sandboxes">self-hosted sandbox</a> can now attach <a href="/docs/en/managed-agents/memory">memory stores</a>. The Python, TypeScript, and Go SDK workers download each attached store into the sandbox at its <code>mount_path</code> and sync the agent’s changes back to the store. See <a href="/docs/en/managed-agents/self-hosted-sandboxes-memory">Memory stores in self-hosted sandboxes</a>.</li>
<li>The session viewer in the Claude Console has been redesigned with a timeline minimap, a transcript grouped by model request, and an Inspector panel for session details and cost, raw events, per-tool statistics, mounted resources, and per-thread activity. See <a href="/docs/en/managed-agents/session-observability#inspect-a-session-in-the-console">Inspect a session in the Console</a>.</li>
</ul>
