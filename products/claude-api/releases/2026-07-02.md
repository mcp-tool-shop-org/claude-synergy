# claude-api — July 2, 2026

<ul>
<li>We’ve added the <code>agent-memory-2026-07-22</code> beta header, which changes how <a href="/docs/en/managed-agents/memory#list-memories">listing memories</a> (<code>GET /v1/memory_stores/{memory_store_id}/memories</code>) behaves: results are returned in a stable, server-defined order and the <code>order_by</code> and <code>order</code> parameters are ignored; <code>depth</code> accepts only <code>0</code>, <code>1</code>, or being omitted (other values return a <code>400</code> error); and <code>path_prefix</code> must end with <code>/</code> and matches whole path segments instead of a substring. Page cursors issued without the header aren’t valid with it, so restart from the first page when you adopt it. On memory store endpoints, <code>agent-memory-2026-07-22</code> replaces <code>managed-agents-2026-04-01</code>; sending both returns a <code>400</code> error. On July 22, 2026, the <code>managed-agents-2026-04-01</code> header adopts the same list behavior. See <a href="/docs/en/api/beta-headers#endpoint-specific-headers">Beta headers</a>.</li>
<li>The Python (0.116.0), TypeScript (0.110.0), Go (1.56.0), Java (2.48.0), Ruby (1.55.0), PHP (0.36.0), C# (12.35.0), and CLI (1.16.0) SDKs now send <code>agent-memory-2026-07-22</code> on all memory store calls instead of <code>managed-agents-2026-04-01</code>. If your code passes <code>betas</code> explicitly on memory store calls, replace <code>managed-agents-2026-04-01</code> with <code>agent-memory-2026-07-22</code> there rather than adding a second value.</li>
</ul>
