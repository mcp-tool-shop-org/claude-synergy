# claude-api — August 27, 2026

<ul>
<li>In Python SDK 1.2.0, TypeScript SDK 0.122.0, Go SDK 1.68.0, Java SDK 2.59.0, Ruby SDK 1.67.0, and C# SDK 12.44.0, <code>client.beta.files</code> and <code>client.beta.skills</code> no longer send the <code>files-api-2025-04-14</code> and <code>skills-2025-10-02</code> beta headers and return the same shapes as <code>client.files</code> and <code>client.skills</code>. With this change, <code>client.beta.skills.delete()</code> deletes a Skill together with all of its versions, and the beta Messages type <code>BetaSkill</code> (the container Skill reference) is renamed <code>BetaContainerSkill</code>. Requests that still send the beta headers keep receiving the beta shapes. See <a href="/docs/en/build-with-claude/files#migrate-from-files-api-2025-04-14">Migrate from <code data-link-continues="before">files-api-2025-04-14</code></a> and <a href="/docs/en/build-with-claude/skills-guide#migrate-from-skills-2025-10-02">Migrate from <code data-link-continues="before">skills-2025-10-02</code></a>.</li>
<li>You can now create <strong>personal keys</strong> and <strong>service account keys</strong> in the Claude Console. They act as you or as a <a href="/docs/en/manage-claude/workload-identity-federation#service-accounts">service account</a>, with the same permissions, and stop working when the linked account is removed from an organization. This lets organization admins more easily track usage for each account, and ensure key usage is legitimate. These API keys can be scoped to a specific workspace or <a href="/docs/en/manage-claude/authentication#select-a-workspace">work on admin endpoints and across any workspace</a> the account has access to. Workspace API keys remain supported as a legacy option. See <a href="/docs/en/manage-claude/authentication#api-keys">API keys in Authentication</a> for more information.</li>
</ul>
