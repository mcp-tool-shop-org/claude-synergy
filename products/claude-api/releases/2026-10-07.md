# claude-api — October 7, 2026

<ul>
<li>We’ve lowered the price of prompt cache reads on Claude Sonnet 5.5 from $0.20 USD to $0.10 USD per million tokens: 0.05x the base input price instead of 0.1x. Cache writes and all other prices are unchanged. See <a href="/docs/en/about-claude/pricing#prompt-caching">Prompt caching pricing</a>.</li>
<li><span id="october-7-2026-4"></span>We’ve launched <strong>Claude Haiku 5.5</strong> (<code>claude-haiku-5-5</code>), our most capable model tuned for high-volume and latency-sensitive work. It has a <a href="/docs/en/build-with-claude/context-windows">1M token context window</a>, 128k max output tokens, and <a href="/docs/en/build-with-claude/thinking">adaptive thinking</a> with the <a href="/docs/en/build-with-claude/effort">effort parameter</a>. It’s available on the Claude API, <a href="/docs/en/build-with-claude/claude-in-amazon-bedrock">Claude in Amazon Bedrock</a>, <a href="/docs/en/build-with-claude/claude-platform-on-aws">Claude Platform on AWS</a>, <a href="/docs/en/build-with-claude/claude-models-on-google-cloud/google-managed">Claude Models on Google Cloud (Google managed)</a>, and <a href="/docs/en/build-with-claude/claude-in-microsoft-foundry">Claude in Microsoft Foundry</a>. See <a href="/docs/en/models/haiku-5-5/whats-new-haiku-5-5">What’s new in Claude Haiku 5.5</a>.</li>
<li>Code written for Claude Haiku 4.5 can break on Claude Haiku 5.5. Manual extended thinking (<code>budget_tokens</code>), the sampling parameters <code>temperature</code>, <code>top_p</code>, and <code>top_k</code>, and assistant message prefill can each return a 400 error. <code>computer_20250124</code> also returns a 400 error: use the <code>computer_toolset_20260801</code> toolset on the Claude API and Google Cloud, or <code>computer_20251124</code> on Amazon Bedrock. A request that sends thinking blocks back after a change to <code>system</code>, <code>tools</code>, or earlier turns can also return a 400 error. Adaptive thinking is on by default, so a response can begin with <code>thinking</code> blocks, and their text is omitted unless you set <code>thinking.display</code> to <code>"summarized"</code>. Claude Haiku 5.5 also uses a tokenizer that produces more tokens for the same text. See the <a href="/docs/en/models/haiku-5-5/migration-guide">Claude Haiku 5.5 migration guide</a> for each change. For model-specific prompting patterns, see <a href="/docs/en/build-with-claude/prompt-engineering/prompting-claude-haiku-5-5">Prompting Claude Haiku 5.5</a>.</li>
<li><span id="october-7-2026-2"></span>Python SDK 1.12.0 and TypeScript SDK 0.132.0 add classes, in beta, for the <a href="/docs/en/agents-and-tools/tool-use/browser-use-tool">browser use tool</a> and the <a href="/docs/en/agents-and-tools/tool-use/computer-use-tool">computer use tool</a>. You subclass one and write one method per tool against your own browser or desktop automation. The SDK runs the tool loop, the URL and file policies you set for the browser, and your approval callback. See <a href="/docs/en/agents-and-tools/tool-use/browser-use-sdk">Browser and computer use with the SDK toolsets</a>.</li>
<li><span id="october-7-2026-3"></span>Claude Max, Ultra, and Team plans now include monthly API credits. To learn how to claim them, see <a href="/docs/en/about-claude/api-credits-for-subscribers">API credits for Max, Ultra, and Team plans</a>.</li>
<li><span id="october-7-2026-5"></span>In Claude Managed Agents, a cloud environment with <code>limited</code> networking now also applies its <code>allowed_hosts</code> to the <code>web_search</code> and <code>web_fetch</code> tools. A <code>web_fetch</code> call for a URL on a host that <code>allowed_hosts</code> does not match returns a <code>url_not_allowed</code> error result to the agent. <code>web_search</code> omits results from such hosts. When <code>allowed_hosts</code> lists no hosts, neither tool returns a page or a search result. <code>allow_package_managers</code> and <code>allow_mcp_servers</code> add no hosts for these tools. To let the tools reach a host, add it to <code>allowed_hosts</code>, which also opens it to the sandbox. <code>unrestricted</code> networking and self-hosted environments do not limit these tools. See <a href="/docs/en/managed-agents/environments#networking">Environment networking</a>.</li>
<li>With <code>limited</code> networking, creating a session fails with a 400 error when an enabled web tool’s <code>allowed_domains</code> has an entry not within <code>allowed_hosts</code>. So does a session update that adds such an entry. An <code>allowed_hosts</code> entry matches one exact host unless it starts with <code>*.</code>, so <code>docs.example.com</code> is not within <code>["example.com"]</code>. To fix the error, add the host to <code>allowed_hosts</code> or remove the entry from <code>allowed_domains</code>. See <a href="/docs/en/managed-agents/tools-web-restrictions">Restrict web search and web fetch domains</a>.</li>
<li>In Claude Managed Agents, the <a href="/docs/en/managed-agents/tools#available-tools"><code data-link-continues="after">web_fetch</code> tool</a> now fetches only URLs that have already appeared in the session, for example in the text of a user message, in a <code>web_search</code> result, or in a page that <code>web_fetch</code> returned earlier. This reduces the risk of data exfiltration. A URL that appears only in Claude’s own output, the agent’s system prompt, an attached document, or the output of a tool such as <code>bash</code>, <code>read</code>, or an MCP tool does not count: a <code>web_fetch</code> call for it returns a <code>url_not_in_prior_context</code> error result to the agent. To let the agent fetch a URL, send it in the text of a <code>user.message</code> event.</li>
</ul>
