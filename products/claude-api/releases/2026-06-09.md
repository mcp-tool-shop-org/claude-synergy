# claude-api — June 9, 2026

<ul>
<li>We’ve launched <strong>Claude Fable 5</strong> (<code>claude-fable-5</code>), our most capable model open to all customers, alongside <strong>Claude Mythos 5</strong> (<code>claude-mythos-5</code>) for Project Glasswing participants. Both models support a <a href="/docs/en/build-with-claude/context-windows">1M token context window</a> by default, 128k max output tokens, and always-on <a href="/docs/en/build-with-claude/thinking">adaptive thinking</a>. See <a href="/docs/en/models/fable-5/overview">Claude Fable 5</a> for specifications, pricing, and availability.</li>
<li>Claude Fable 5 and Claude Mythos 5 use the tokenizer introduced with Claude Opus 4.7. Compared to models before Claude Opus 4.7, the same text produces roughly 30% more tokens. The exact increase depends on the content and workload shape. Use the token counting API with <code>model: "claude-fable-5"</code> to measure your prompts under the new tokenizer. See <a href="/docs/en/build-with-claude/token-counting#token-counts-on-claude-fable-5">Token counts on Claude Fable and Claude Mythos models</a>.</li>
<li>Claude Fable 5 runs safety classifiers on requests and during response generation. When a classifier declines a request, the Messages API returns <code>stop_reason: "refusal"</code>. You are not billed for a request refused before any output is generated. An opt-in <code>fallbacks</code> parameter (in beta on the Claude API and Claude Platform on AWS; not supported on the Message Batches API) re-runs refused requests on another model, billed at the fallback model’s rates. See <a href="/docs/en/build-with-claude/handling-stop-reasons">Handling stop reasons</a>.</li>
<li>The <a href="/docs/en/build-with-claude/refusals-and-fallback#refusal-response"><code>stop_details.category</code></a> field on refusal responses now includes <code>"reasoning_extraction"</code> on Claude Fable 5, returned when a request is blocked under Anthropic’s Terms of Service restrictions on reverse engineering or duplicating model outputs. The existing <code>"cyber"</code> and <code>"bio"</code> categories are unchanged. No beta header is required.</li>
<li>On Claude Fable 5 and Claude Mythos 5, <a href="/docs/en/build-with-claude/thinking">adaptive thinking</a> is the only thinking mode: <code>thinking: {"type": "disabled"}</code> is not supported, and manual extended thinking budgets and assistant prefill are not supported (both return a 400 error).</li>
<li>On Claude Fable 5 and Claude Mythos 5, <code>thinking.display</code> defaults to <code>"omitted"</code>, the same as Claude Opus 4.8, Claude Opus 4.7, and Claude Mythos Preview; set <code>display: "summarized"</code> to receive readable thinking summaries. The raw chain of thought is never returned; pass thinking blocks back unchanged in multi-turn conversations on the same model. See <a href="/docs/en/build-with-claude/thinking#thinking-output-on-claude-fable-5-and-claude-mythos-5">Thinking output on Claude Fable 5 and Claude Mythos 5</a>.</li>
<li>Claude Fable 5 requires 30-day data retention and is not available under zero data retention. See <a href="/docs/en/manage-claude/api-and-data-retention#model-specific-data-retention-requirements">Model-specific data retention requirements</a>.</li>
<li>Claude Managed Agents now supports <a href="/docs/en/managed-agents/scheduled-deployments">scheduled deployments</a>, letting you run sessions on a cron schedule without managing your own scheduler.</li>
<li>Claude Managed Agents vaults now support <a href="/docs/en/managed-agents/vaults#add-a-credential">environment variable credentials</a>, so you can securely inject secrets into the agent’s sandbox for CLIs, SDKs, and other services that authenticate through environment variables.</li>
<li>The <a href="/docs/en/manage-claude/compliance-api">Compliance API</a> <a href="/docs/en/manage-claude/compliance-activity-feed">Activity Feed</a> (<code>GET /v1/compliance/activities</code>) is now available on <a href="/docs/en/build-with-claude/claude-platform-on-aws">Claude Platform on AWS</a>. See <a href="/docs/en/api/claude-platform-on-aws-iam-actions#compliance">Compliance IAM actions for Claude Platform on AWS</a> for the <code>ListComplianceActivities</code> action that authorizes it.</li>
<li>The <code>session.thread_*</code> webhook events now include a <code>session_thread_id</code> field identifying the multiagent thread that triggered the event.</li>
<li>We’ve released a <a href="/docs/en/cli-sdks-libraries/libraries/apple-foundation-models">Swift package</a> in beta that adds Claude as a server-side <code>LanguageModel</code> in Apple’s Foundation Models framework. Call Claude through the same <code>LanguageModelSession</code> API as Apple’s on-device model on iOS 27, macOS 27, visionOS 27, and watchOS 27 (beta).</li>
</ul>
