<p>Copilot is now one connected experience in the cloud. Start a cloud task wherever you are, on github.com, GitHub Mobile, the Copilot CLI, the Copilot app, VS Code, or right from a conversation in Slack or Microsoft Teams. Then pick it up wherever you work next.</p>
<p>By default, every session runs in a secure cloud sandbox that starts fast and resumes right where you left off. The compute behind it can now be drawn from your included Actions entitlement, the same one that already runs your builds. That entitlement is now one flexible pool you can use for builds, cloud sandboxes, and, on Team and Enterprise Cloud, larger hosted runners.</p>
<p>The new Copilot cloud experience across surfaces (e.g., Web, Mobile, App, CLI, VS Code, Slack, and Microsoft Teams) and cloud sandboxes are both generally available on paid Copilot plans.</p>
<h2 id="why-this-new-connected-experience-matters"><a class="heading-link" href="#why-this-new-connected-experience-matters">Why this new connected experience matters<span class="heading-hash pl-2 text-italic text-bold" aria-hidden="true"></span></a></h2>
<p><img decoding="async" loading="lazy" src="https://github.com/user-attachments/assets/975814c6-691b-45c6-9ebc-d79b1d111d7e" alt="Image showing a session in VSCode with the cloud option selected"></p>
<ul>
<li><strong>One session, every surface.</strong> Start a change on your phone with voice or a screenshot, continue it on the web, and finish it in the Copilot app, VS Code, or CLI. It’s the same session the whole way, and every surface shows the same session list.</li>
<li><strong>Secure ephemeral isolated environments for agents that start fast and resume where you left off.</strong> By default, every session runs in a cloud sandbox, which is a secure environment on GitHub-managed infrastructure, separate from your local machine. Sandboxes start fast and have no one-hour limit on total running session time. When a sandbox shuts down, it saves a snapshot, so you can resume the session later from any surface. Cloud sandboxes let you run agents without being limited by your local machine’s compute resources.</li>
<li><strong>Flexible compute entitlement.</strong> Your included Actions compute entitlement is now one shared, dollar-based pool instead of a fixed number of standard runner minutes. It covers standard GitHub-hosted runners, cloud sandboxes, and, on Team and Enterprise Cloud, larger hosted runners. You can choose the compute that best fits each task, and each product keeps its own published rate.</li>
</ul>
<h2 id="start-cloud-sessions-and-continue-your-work-anywhere"><a class="heading-link" href="#start-cloud-sessions-and-continue-your-work-anywhere">Start cloud sessions and continue your work anywhere<span class="heading-hash pl-2 text-italic text-bold" aria-hidden="true"></span></a></h2>
<p><img decoding="async" loading="lazy" src="https://github.com/user-attachments/assets/4716f12c-7810-4f05-af7a-69d9f945a10d" alt="Image showing Copilot addressing Copilot Code Review feedback in the pull request window"></p>
<p>On github.com and GitHub Mobile, you can chat and kick off code changes in the same conversation, with the same deep integration with your GitHub workflow as Copilot Chat and Copilot coding agent. Ask a question across multiple repositories in an organization or pick a repository for a code change. In Slack or Teams, mention @GitHub to create an issue, request a code change, or investigate a bug.</p>
<ul>
<li><strong>Start from anywhere:</strong> Kick off a cloud session from github.com, the Copilot CLI, the Copilot app, VS Code, or the redesigned Copilot experience on GitHub Mobile. On mobile, start a new session from the <strong>Copilot</strong> tab, or select <strong>New agent session</strong> from any pull request, issue, or repository to get started right where you’re working.</li>
<li><strong>Describe the task your way:</strong> On GitHub Mobile, describe a task by voice or attach an image or file. On the web, attach repositories, Copilot Spaces, or files with the <strong>(+)</strong> menu or <code>@</code>. In Slack and Teams, Copilot can use messages and threads as context.</li>
<li><strong>Unified context across surfaces:</strong> On github.com, when you open Copilot over a pull request, file, or repository, it adds that page as context. Your sessions follow you, and pins sync across the web and mobile.</li>
<li><strong>Steer local sessions from your phone:</strong> Register your local device through GitHub Mission Control as an environment in the Copilot CLI or VS Code, then start and steer your sessions on the go with GitHub Mobile (iOS, Android).</li>
</ul>
<p>For more information, see the <a href="https://docs.github.com/en/copilot/concepts/copilot-surfaces/copilot-on-github?utm_source=cloud-changelog-overview-docs&amp;utm_medium=changelog&amp;utm_campaign=universe-2026">documentation on using Copilot in a cloud environment</a>.</p>
<h2 id="give-copilot-the-tools-context-it-needs"><a class="heading-link" href="#give-copilot-the-tools-context-it-needs">Give Copilot the tools &amp; context it needs<span class="heading-hash pl-2 text-italic text-bold" aria-hidden="true"></span></a></h2>
<p><img decoding="async" loading="lazy" src="https://github.com/user-attachments/assets/82fce46f-08ca-49ff-b872-eda290fafe9f" alt="Image of Connectors tab showing installed MCP servers for Azure Data Explorer, LaunchDarkly, Sentry, Slack, WorkIQ, and two of the user's custom MCPs"></p>
<p>Cloud sessions have the same tools as the Copilot CLI and Copilot app, plus ways to bring in context and customize how Copilot works:</p>
<ul>
<li><strong>Tools:</strong> Bash and the GitHub CLI work alongside code search for everyday tasks, such as tracing a bug to a specific pull request or bulk-moving issues between epics.</li>
<li><strong>Connectors and MCP:</strong> Built-in connectors bring in context from Sentry, Linear, Cloudflare, and more. Set them up once in the <a href="https://github.com/copilot/customize?utm_source=cloud-changelog-customize-tab&amp;utm_medium=changelog&amp;utm_campaign=universe-2026"><strong>Customize</strong></a> menu on GitHub or in the Copilot app, and they work in every cloud session. You can also configure local or remote custom MCP servers that require key-based authentication. For Slack and Teams, <a href="https://docs.github.com/copilot/how-tos/copilot-on-github/customize-copilot/configure-mcp-servers?utm_source=cloud-changelog-mcp-docs&amp;utm_medium=changelog&amp;utm_campaign=universe-2026">repository-level MCP servers</a> let you connect tools and bring more context into shared sessions.</li>
<li><strong>Skills:</strong> Agent skills teach Copilot repeatable workflows with your own instructions, scripts, and resources.</li>
<li><strong>Slash commands:</strong> <code>/rubber-duck</code>, <code>/context</code>, and more now work on github.com and GitHub Mobile.</li>
<li><strong>Permissions:</strong> Choose how much autonomy the agent gets. Copilot asks for approval before any tool call that requires it. See <a href="https://docs.github.com/copilot/how-tos/copilot-cli/use-copilot-cli/allowing-tools?utm_source=cloud-changelog-allow-tools-docs&amp;utm_medium=changelog&amp;utm_campaign=universe-2026">our docs about permissions</a> to learn more. </li>
</ul>
<h2 id="run-on-copilot-on-secure-cloud-sandboxes"><a class="heading-link" href="#run-on-copilot-on-secure-cloud-sandboxes">Run on Copilot on secure cloud sandboxes<span class="heading-hash pl-2 text-italic text-bold" aria-hidden="true"></span></a></h2>
<p><img decoding="async" loading="lazy" src="https://github.com/user-attachments/assets/f5718287-02f5-4eec-947c-140cb81d28f4" alt="Image showing cloud and local in the Copilot App environment picker. Cloud is selected."></p>
<p>By default, every session runs Copilot in a secure cloud sandbox. These cloud sandboxes are a secure, fast, and resumable execution environment on GitHub-managed infrastructure. Snapshots let you resume a session later from any surface.</p>
<p>Billing for cloud sandbox usage begins in November 2026. Free usage will draw from the shared compute entitlement described in the next section.</p>
<ul>
<li><strong>Actions environments:</strong> If you use Actions-based self-hosted runners or <code>copilot-setup-steps.yml</code>, you still need to use Actions as the environment for your session.</li>
<li><strong>Self-hosted environments:</strong> Run the Copilot CLI with <code>--environment-host</code> to register your own computer or VM as an environment in your Copilot clients.</li>
</ul>
<h2 id="a-unified-flexible-way-to-use-your-actions-entitlement"><a class="heading-link" href="#a-unified-flexible-way-to-use-your-actions-entitlement">A unified, flexible way to use your Actions entitlement<span class="heading-hash pl-2 text-italic text-bold" aria-hidden="true"></span></a></h2>
<p>Your included Actions entitlement is now one shared, dollar-based compute entitlement, instead of a fixed number of standard runner minutes. It’s the same value, and you can now use it across:</p>
<ul>
<li>Standard GitHub-hosted runners.</li>
<li>Cloud sandboxes, including the Copilot sandboxes behind your cloud sessions.</li>
<li>Larger hosted runners, on Team and Enterprise Cloud.</li>
</ul>
<p>Usage draws from one shared entitlement, while each product keeps its own published meter and rate. Choose the compute that best fits your work.</p>
<p>For the latest pricing and included compute by plan, see <a href="https://docs.github.com/billing/reference/product-usage-included?utm_source=cloud-changelog-pricing-docs&amp;utm_medium=changelog&amp;utm_campaign=universe-2026">product usage included with each plan</a>.</p>
<p>How it works:</p>
<ul>
<li>Usage is deducted at each product’s published rate, so higher-rate compute uses the entitlement faster.</li>
<li>The entitlement resets at the start of each billing cycle. Usage beyond it follows your existing rates, budgets, and payment settings.</li>
</ul>
<p>The flexible Actions compute entitlement change applies to GitHub Free, Pro, Free for organizations, Team, and Enterprise Cloud. Larger hosted runners draw from the entitlement only on Team and Enterprise Cloud. Billing for cloud sandbox usage begins November 2026 and draws from your included Actions entitlement.</p>
<h2 id="manage-cloud-access-and-permissions"><a class="heading-link" href="#manage-cloud-access-and-permissions">Manage cloud access and permissions<span class="heading-hash pl-2 text-italic text-bold" aria-hidden="true"></span></a></h2>
<p>Access to cloud experiences, including Copilot on github.com and GitHub Mobile, is governed by the policy in <a href="https://github.com/settings/copilot/features?utm_source=cloud-changelog-policy-setting&amp;utm_medium=changelog&amp;utm_campaign=universe-2026">Copilot settings</a> titled “Copilot in the cloud”. If you previously had cloud agent enabled, but opted a repository out of Copilot cloud agent, this repository exclusion will be brought over into the new experience.</p>
<p>If your organization has configured enterprise-managed settings for agent permissions or MCP server allowlists, these will apply to the updated cloud experience. For more information, see <a href="https://docs.github.com/enterprise-cloud@latest/copilot/reference/enterprise-administrators/enterprise-managed-settings?utm_source=cloud-changelog-enterprise-keys-docs&amp;utm_medium=changelog&amp;utm_campaign=universe-2026#supported-keys">supported enterprise keys in the cloud</a>.</p>
<p>To ensure data security, chat sessions are scoped to a single organization or your personal repositories by default. Members of an organization will have to use single sign-on to access session data from a repository associated with that organization.</p>
<p>If you do not have write access to a repository you’re looking at, your Copilot use in that repository will automatically be read-only.</p>
<p>See more on <a href="https://docs.github.com/copilot/how-tos/administer-copilot/manage-for-enterprise/manage-agents/manage-copilot-in-the-cloud?utm_source=cloud-changelog-admin-docs&amp;utm_medium=changelog&amp;utm_campaign=universe-2026">managing access and permissions in the cloud</a>.</p>
<h2 id="getting-started"><a class="heading-link" href="#getting-started">Getting started<span class="heading-hash pl-2 text-italic text-bold" aria-hidden="true"></span></a></h2>
<p>The new Copilot cloud experience is available on paid Copilot plans only and is rolling out to users starting October 28th. Copilot Free users can continue to use Copilot Chat on github.com and GitHub Mobile and can get the updated experience by upgrading their Copilot plan. Cloud sandbox usage can now be drawn from your included Actions entitlement.</p>
<p>Go to the <a href="https://github.com/copilot?utm_source=cloud-changelog-main-chat-cta&amp;utm_medium=changelog&amp;utm_campaign=universe-2026">GitHub Copilot page</a> or the <strong>Agents</strong> tab in a repository or open the <strong>Copilot</strong> tab in GitHub Mobile. To start or continue a cloud session from Copilot CLI, the Copilot app, or VS Code, see our documentation.</p>
<p>Onboarding in Slack and Microsoft Teams is now simpler. With the required organization policies enabled, install or upgrade the GitHub app and connect your GitHub account to start working with @GitHub.</p>
<p>Join the discussion on the <a href="https://github.com/orgs/community/discussions/211011?utm_source=cloud-changelog-community-discussion&amp;utm_medium=changelog&amp;utm_campaign=universe-2026">GitHub Community</a>.</p>
